# 027 — Пустые ответы API («Что-то пошло не так» на карточке анонса)

Статус: готово (2026-10-05)

## Проблема
У водителя без анонса синяя карточка на главной показывала «Что-то пошло не так».
`GET /arrivals/me` и `/arrivals/last-template` при отсутствии данных возвращают `null` → NestJS отдаёт **пустое тело без Content-Type** → Dio кладёт в `res.data` пустую строку `''`, а не `null` → `'' as Map<String, dynamic>` падает. Тесты 015 не поймали: в них репозиторий подменён, реального HTTP-ответа нет.

## Уже сделано (коммит в чате)
- `arrival_repository.dart`: `data is Map<String, dynamic> ? … : null` в `mine()` и `lastTemplate()`.
- На карточке анонса при ошибке — кнопка «Повторить».

## Что сделать
1. Бэкенд: эндпоинты, которые могут вернуть «ничего», отдают явный JSON — `{ "arrival": null }` / `{ "template": null }` (или 204), не голый `null`. Пройтись по всем контроллерам (`grep` на `: null` / `return null` в сервисах, отдаваемых наружу).
2. Клиент: обновить разбор под новый формат.
3. Тест репозитория через Dio с mock-адаптером: тело `''` без Content-Type и `{ "arrival": null }` → `mine()` возвращает `null`, без исключения.
4. Ошибку в `error:`-ветках провайдеров логировать (`debugPrint` с типом исключения) — сейчас она молча превращается в «Что-то пошло не так», и причину не видно.

## Готово, когда
- Новый водитель без анонсов видит на главной кнопку «Буду на точке», а не ошибку (проверено на устройстве).
- Тест на пустой ответ зелёный.

## Что сделано (2026-10-05)
1. `GET /arrivals/me` и `/arrivals/last-template` переведены на явную
   JSON-обёртку (`{ arrival: Arrival | null }` / `{ template: ... | null }`) —
   `arrivals.service.ts`. `repeat()` обновлён на новую форму внутреннего
   вызова `getLastTemplate()`.
2. `arrival_repository.dart`: `mine()`/`lastTemplate()` читают из обёртки,
   но проверка `data is Map<String, dynamic>` оставлена как защита от
   пустого тела без Content-Type (старое поведение/прокси) — не только от
   нового формата.
3. Новый `packages/lubao_core/test/arrival_repository_test.dart` — Dio с
   фейковым `HttpClientAdapter`: пустое тело без Content-Type,
   `{"arrival": null}`/`{"template": null}`, и валидные данные — все 6
   случаев зелёные.
4. Во всех 20 местах кодовой базы, где `AsyncValue.when(error: (e, st) => ...)`
   молча превращал исключение в «Что-то пошло не так» — добавлен
   `debugPrint('<Screen>: $e')` перед отрисовкой `ErrorView`/эквивалента, во
   всех экранах водителя, логиста и общих (список — `git show` этого
   коммита). Причина ошибки теперь видна в консоли при разборе багов, а не
   теряется.
5. Также причёсаны по пути (попутно обнаружено той же итерацией по коду):
   не найдено других эндпоинтов, отдающих bare `null` как весь ответ —
   `grep` по сервисам показал только эти два места.

Полный `flutter analyze`/`flutter test` (lubao_core + lubao_app) и backend
`jest` (123/123) — зелёные.
