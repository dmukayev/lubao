# 027 — Пустые ответы API («Что-то пошло не так» на карточке анонса)

Статус: основное исправлено в чате (2026-10-05) · остались тест и правило · 30 минут, перед 026.

## Проблема
У водителя без анонса синяя карточка на главной показывала «Что-то пошло не так».
`GET /arrivals/me` и `/arrivals/last-template` при отсутствии данных возвращают `null` → NestJS отдаёт **пустое тело без Content-Type** → Dio кладёт в `res.data` пустую строку `''`, а не `null` → `'' as Map<String, dynamic>` падает. Тесты 015 не поймали: в них репозиторий подменён, реального HTTP-ответа нет.

## Уже сделано (коммит в чате)
- `arrival_repository.dart`: `data is Map<String, dynamic> ? … : null` в `mine()` и `lastTemplate()`.
- На карточке анонса при ошибке — кнопка «Повторить».

## Что сделать
1. Бэкенд: эндпоинты, которые могут вернуть «ничего», отдают явный JSON — `{ "arrival": null }` / `{ "template": null }` (или 204), не голый `null`. Пройтись по всем контроллерам (`grep` на `: null` / `return null` в сервисах, отдаваемых наружу).
2. Клиент: обновить разбор под новый формат.
3. Тест репозитория через Dio с mock-адаптером: тело `''` без Content-Type и `{ "arrival": null }` → `mine()` возвращает `null`, без исключения.
4. Ошибку в `error:`-ветках провайдеров логировать (`debugPrint` с типом исключения) — сейчас она молча превращается в «Что-то пошло не так», и причину не видно.

## Готово, когда
- Новый водитель без анонсов видит на главной кнопку «Буду на точке», а не ошибку (проверено на устройстве).
- Тест на пустой ответ зелёный.
