# 066 — Компания публикует грузы без проверки; плашка «Проверена»

Статус: **готово** (2026-10-13).
- п.1 ✅ `COMPANY_NOT_VERIFIED` из публикации убран; нужен только телефон логиста. У непроверенной компании — не больше 10 активных (`PUBLISHED`) грузов, 11-й → 403 `COMPANY_ACTIVE_LIMIT`. «Повторить» — тот же create, лимит общий. Отдельного «восстановления из архива» в коде нет (архивный груз обратно в ленту не возвращается), поэтому отдельной проверки для него не понадобилось. В статистику цен идут только грузы проверенных компаний.
- п.2 ✅ `assertCompanyMayContactDriver` удалён: номера водителей (карточка, чат) и фото машин непроверенной компании открываются так же, как проверенной. Суточный лимит (`consume`, ≈30) и `contact_events` действуют для компаний как раньше; e2e API подтверждает, что номер выдаётся.
- п.3 ✅ `CompanyVerifiedBadge`: «Проверена» — зелёная иконка `badgeCheck`, «Не проверена» — серым мелко. Где показано: лента, карточка груза, «Мои рейсы» (отклики, сделки, избранное), сделка, шапка чата, «Все грузы компании», страница «Поделиться» (груз и компания). ARB — 4 языка.
- п.4 ✅ Форма груза больше не блокируется баннером. На `COMPANY_ACTIVE_LIMIT` / `COMPANY_PAUSED` открывается окно с понятным текстом и кнопкой «Пройти проверку» (ведёт в профиль, к загрузке свидетельства). Карточка «можно / нельзя» и баннер профиля переписаны.
- п.5 ✅ «Требует внимания»: «Не проверены, грузы в ленте» и «На паузе после жалоб»; у списка компаний новые фильтры. Пауза: жалобы двух разных водителей на непроверенную компанию — на её груз (новое «Пожаловаться на груз» в карточке), на сделку с ней или на саму компанию; отклонённые админом не считаются. После этого `Company.publishingPausedAt` — грузы скрыты из ленты, «Поделиться» и избранного, новые → `COMPANY_PAUSED`. В карточке компании в админке — плашка и «Снять паузу» (с причиной; старые жалобы больше не считаются). Проверка компании тоже снимает паузу. Миграция `20261013120000_company_publishing_pause` — две nullable-колонки, старые строки не затрагиваются.
- п.6 ⏸ не делалось: подходящего официального API нет. Поиск по БИН на stat.gov.kz доступен только после входа, документированного публичного API нет. Выписка из ГБД ЮЛ на egov.kz (услуга 3006) — госуслуга с ЭЦП или SMS-паролем. На data.egov.kz открытого набора ЮЛ по БИН без ключа и договора найти не удалось. Парсинг по условию задачи не делаем. Вернуться к пункту, если владелец получит доступ к API (договор с БНС/ГБД ЮЛ).
- п.7 ✅ e2e:

  - `e2e-admin-api` — лимит, `COMPANY_ACTIVE_LIMIT`, жалобы → пауза → скрыто из ленты → `COMPANY_PAUSED` → снятие, номер водителя непроверенной компании;

## Что сделать
1. **Бэкенд, публикация:**
   - убрать `COMPANY_NOT_VERIFIED` из `cargos.service.create`;
   - требования к рег. номеру и свидетельству перед первой публикацией снять, обязательным остаётся только телефон логиста;
   - для непроверенной компании — не больше **10 активных** грузов. На 11-й — ошибка `COMPANY_ACTIVE_LIMIT` (тот же лимит при «Повторить» и восстановлении из архива).
2. **Телефоны водителей:** `assertCompanyMayContactDriver` убрать — непроверенная компания видит номера, как проверенная. Общий лимит ≈30 открытий в сутки и запись в `contact_events` остаются; проверить, что лимит действует и для компаний.
3. **Плашка:**
   - «Проверена» с зелёной галочкой (иконка, не эмодзи) у названия компании: лента водителя, карточка груза, отклик, чат, профиль компании, публичная страница «Поделиться»;
   - у непроверенной — серое «Не проверена», мелко;
   - ARB, 4 языка.
4. **Приложение логиста:**
   - баннер «Пройдите проверку» больше не блокирует «+ Груз»;
   - при лимите — понятный текст и кнопка «Пройти проверку»;
   - «Ясно, что доступно до проверки» — обновить карточку «можно / нельзя».
5. **Админка:**
   - «Требует внимания» — непроверенные компании с активными грузами;
   - 2 жалобы на компанию → публикация на паузе (грузы скрыты из ленты), снять паузу может админ.
6. **Автопроверка КЗ по БИН** (можно отдельным коммитом):
   - выяснить доступный официальный источник (stat.gov.kz / egov API / data.egov.kz), без парсинга, если есть API;
   - название и статус «действующее» совпали → `isVerified`, пометка «проверена автоматически», админ может отозвать;
   - если подходящего API нет — записать в статус задачи и не делать.
7. **e2e:** в сценарии логиста новая компания без проверки публикует груз; 11-й груз упирается в лимит; у водителя в ленте видно «Не проверена» и «Проверена».
