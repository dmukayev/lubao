## Проблема (ревью 2026-10-05, после 026)
- Сводка — витрина: плитки не нажимаются, перейти к «64 груза» или «23 сделки» некуда.
- Разделов «Грузы», «Сделки», «Настройки» нет, хотя цифры по ним на сводке есть.
- Админ ничего не может исправить: имя/телефон/город водителя, машину, реквизиты компании, справочники (только создание).

## Этап A. Меню и сводка (макет 16)
1. Меню (слева, порядок): Сводка · Проверка · Жалобы · Водители · Компании · **Грузы** · **Сделки** · Справочники · **Настройки**. Счётчики на «Проверка» и «Жалобы».
2. `GET /admin/stats?period=today|7d|30d` — к текущим цифрам добавить: прирост за период (водители, компании, грузы, доставлено), «на точке сегодня» (`ON_SITE` + `PLANNED` на сегодня) и «на неделе».
3. **Каждая плитка — ссылка на список с фильтром** (через query-параметры в адресе, чтобы фильтр сохранялся при перезагрузке и копировании ссылки): водители → `/drivers`, компании → `/companies`, на точке → `/drivers?onSite=today`, грузы → `/cargos?status=PUBLISHED`, в работе → `/deals?status=active`, доставлено → `/deals?status=DELIVERED`.
4. Блок **«Требует внимания»** — `GET /admin/attention`: документы на проверке (кол-во людей + возраст самого старого), открытые жалобы, сделки без движения > 3 дней (по `updatedAt` и статусу не `DELIVERED/CANCELLED`), компании без проверки, новые города (`PENDING`). Каждая строка → список с фильтром. Красный счётчик, если старше 24 ч.
5. **Последние события** — последние 10 записей из `audit_log` + регистрации/новые грузы/смены статусов сделок (одна лента, ссылки на сущности). «Журнал →» — полный список `/audit` с фильтрами (кто, сущность, период).
6. Глобальный поиск сверху: имя, телефон, email, госномер, № груза/сделки → выпадающий список результатов по типам.

## Этап B. Проверка целиком (макет 19)
7. Очередь — **по субъектам**, не по документам: `GET /admin/verification/queue?type=driver|company` → человек/компания, у которых есть хотя бы один `PENDING`; сортировка — кто ждёт дольше (по самому старому `PENDING`). В строке — причина: «Новый · N документов» / «Повторно: <тип>» / «Сменил машину».
8. `GET /admin/verification/drivers/:id` → профиль для сверки (имя, госномер тягача, прицеп, кузов/тоннаж) + **все** документы водителя (и одобренные — для сравнения) с presigned-ссылками.
9. Экран: слева очередь, справа — шапка водителя (+ «Карточка →»), блок **«Сверка с профилем»** (строки: имя ↔ права, лицо на селфи ↔ фото в правах, госномер ↔ техпаспорт тягача, прицеп ↔ техпаспорт прицепа; админ кликом ставит «совпадает / не совпадает»; отметки сохраняются в `audit_log` вместе с решением), **большой просмотр** документа (увеличить/уменьшить/повернуть, колесо мыши и перетаскивание; «Рядом с селфи» — два документа бок о бок), лента миниатюр всех документов с цветной точкой статуса.
10. Решение по каждому документу сохраняется («Документ в порядке» / «Есть проблема…» — причина из списка: нечитаемое фото, документ просрочен, не совпадает имя, не совпадает госномер, другое + текст). Но **итог — один на водителя**:
    - «Подтвердить водителя» — активна, когда все обязательные документы (`REQUIRED_DRIVER_DOC_TYPES`) одобрены → `isVerified = true`, одно push/SMS «Профиль проверен» (через модуль уведомлений, если 011 ещё нет — запись в лог и TODO);
    - «Вернуть на доработку» — отклоняет отмеченные документы с причинами, водитель получает **одно** уведомление со списком «что переснять»; в приложении в чек-листе профиля — причина у каждого документа.
11. То же для компаний (вкладка «Компании»): сверка названия и рег. номера с лицензией.
12. **Увеличение не открывается — починить.** Вероятная причина: presigned-ссылка MinIO с другого origin, браузер блокирует загрузку картинки (CORS) → настроить CORS бакета документов для origin админки (dev: `http://localhost:5566`; prod — через переменную окружения) **или** отдавать картинку через бэкенд-прокси `GET /admin/documents/:id/file` (только для ADMIN, с той же 10-минутной ссылкой). Выбрать прокси, если CORS на MinIO в docker-compose настраивается неудобно. Проверить в Chrome: миниатюра, полноэкранный просмотр, PDF (если загружен PDF — открывать в новой вкладке).
13. Пустая страница `/#/verification` (сообщение пользователя 2026-10-05) — найти по консоли браузера и исправить; в новом экране при пустой очереди — «Все проверены 👍», при ошибке — «Что-то пошло не так» + «Повторить».

## Этап C. Грузы и сделки (макет 17)
14. `/cargos` — таблица: №, маршрут (точка → страна/город), груз, кузов/вес, цена + валюта, компания/логист, откликов, статус, опубликован. Фильтры: статус, компания, страна назначения, период; поиск по №. Пагинация 50.
15. Карточка груза `/cargos/:id`: все поля, фото, отклики (водители — ссылки), сделка (если есть), история. Действия: **«Снять с публикации»** (причина обязательна, логисту уведомление), **«Исправить»** (те же поля, что при публикации; причина обязательна).
16. `/deals` — таблица: №, маршрут, водитель, компания, цена, статус, «без движения N дней», создана. Фильтры: статус (в т.ч. `active` = не `DELIVERED/CANCELLED`), «без движения > 3 дней», водитель, компания, период.
17. Карточка сделки `/deals/:id` (макет 17): шапка (маршрут, статус, плашка «N дней без движения», цена + пересчёт в ₸, ссылка на груз), карточки водителя и компании (→ их карточки), **история статусов** (кто и когда, из полей `*At` + `audit_log`), звонки (`contact_events`), вкладки «Переписка · Звонки · Журнал».
    - Переписка — **только просмотр** (оригинал + перевод), без правки и удаления; каждое открытие чата админом пишется в `audit_log` (доступ к личной переписке).
    - **«Исправить статус»** — только на соседний статус (вперёд/назад на один шаг), причина обязательна, обе стороны получают уведомление.
    - **«Отменить сделку»** — причина обязательна, `cancelledByRole = ADMIN` (добавить значение в enum с переводом — см. правило миграций в CLAUDE.md), рейтинг сторон отменой от админа не затрагивается.

## Этап D. Редактирование (макет 18)
18. Общий паттерн: в карточке кнопка «Редактировать» → боковая панель справа поверх карточки; внизу — **«Причина изменения»** (обязательно) и «Сохранить». В `audit_log` — старые и новые значения по каждому полю + причина. В журнале карточки это видно.
19. **Водитель**: имя, телефон, домашний город (поиск как в 021), машина (кузов, тонн, длина, госномер, марка), страны / «любая», допуски.
    - смена телефона → проверка уникальности, `sessions.revokeAllForUser`, предупреждение в панели;
    - смена кузова/госномера тягача → `VEHICLE_PASSPORT` на повторную проверку (`RESUBMIT`/`PENDING`), прицепа → `TRAILER_PASSPORT`; селфи и права не трогаются (решение 2026-10-04, п. «Профиль водителя»); `isVerified` пересчитывается.
20. **Компания**: название, название по-русски, страна, город, юр. адрес, рег. номер; сотрудники — сменить роль, удалить из компании (не последнего владельца), передать владение; email сотрудника — с отзывом его сессий.
21. **Справочники** — полноценное редактирование: названия на 4 языках (kk/ru/zh/en), включить/выключить, порядок; для точек — город и координаты; для городов — область и координаты (нужны для «Близко к дому», задача 016). Удалять запрещено, если запись используется — только выключать.
22. **Настройки** `/settings` (эндпоинты `GET/PATCH /admin/settings` уже есть): точка по умолчанию (`defaultPointCityId`), радиус «Близко к дому» (`homeRadiusKm`, по умолчанию 200), срок архива груза (3 дня). Каждое изменение — в `audit_log`.
23. **Нельзя редактировать** (в панелях этих полей нет; бэкенд отклоняет): рейтинг и число отзывов, отзывы (только «Скрыть» с причиной), переписку и звонки, журнал, файлы документов (только одобрить/отклонить).

## Этап E. Жалобы (макет 20)
24a. **Баг:** список жалоб запрашивает только `status=OPEN` → после «В работе» жалоба исчезает и её нигде не найти. Сделать вкладки **«Новые · N / В работе · N / Закрытые»** (`OPEN` / `IN_REVIEW` / `RESOLVED+REJECTED`), фильтр «мои».
24b. Схема `Complaint`: `assignedToUserId` + `takenAt` (кто взял в работу), `resolution` (enum: `DISMISSED` — не подтвердилась, `WARNED` — предупреждение, `CARGO_UNPUBLISHED` — груз снят, `BLOCKED` — блокировка), `resolutionNote` (ответ автору). Миграция — по правилу CLAUDE.md (старые `RESOLVED` → `resolution = WARNED`? нет: `NULL` допустим для старых записей).
24c. Экран: слева очередь, справа — жалоба: заголовок и причина, **кто пожаловался** и **на кого** (карточки-ссылки; у нарушителя — «ещё N жалоб за месяц»), **контекст**: груз (с ценой в объявлении), сообщение из чата (оригинал + перевод), сделка — что применимо к `targetType`; комментарий автора.
24d. Справа — **«Решение»**: один из 4 вариантов; «Снять груз» и «Заблокировать» выполняют действие сразу (те же эндпоинты, что в карточках, с причиной = текст жалобы); **«Ответ автору жалобы»** обязателен → автор получает уведомление и видит ответ в приложении на своём языке («Мои жалобы» в профиле — статус и ответ). Нарушителю при «Предупредить» — уведомление/письмо с текстом причины.
24e. «Взять в работу» — назначает на текущего админа; «Вернуть в новые» — снимает назначение. Всё — в `audit_log`. На сводке «Открытые жалобы» = новые + в работе.

## Готово, когда
- С любой плитки и строки «Требует внимания» — переход в список с нужным фильтром; ссылка со фильтром открывается после перезагрузки.
- Проверка открывает **водителя целиком**: все документы, сверка с профилем, большой просмотр с увеличением и «рядом с селфи»; одно решение — «Подтвердить» или «Вернуть на доработку» с одним уведомлением.
- Жалоба «в работе» не исчезает: вкладки Новые / В работе / Закрытые; закрытие — с решением и ответом автору, решение «снять груз» / «заблокировать» выполняется сразу.
- Есть разделы «Грузы» и «Сделки» с карточками; переписка в сделке только для просмотра; статус исправляется только на соседний и с причиной.
- Админ исправляет данные водителя и компании через боковую панель; каждое изменение с причиной и old/new в журнале; рейтинг и отзывы изменить нельзя.
- Справочники и настройки редактируются из админки.
- `flutter analyze` / `flutter test` / backend-тесты — чисто.
