# 009 — Профиль водителя по макету 07

Статус: не начато · можно делать параллельно с 007

Эталон: `design/screens/07-driver-profile.png`. Решение — `docs/decisions.md` (2026-10-04, «Верификация водителя — в профиле»).

## Текущее состояние (ревью 2026-10-04)
- `driver_profile_screen.dart`: имя, рейтинг, плашка проверен/не проверен, телефон, язык, выход. Верификация — карточка с прогрессом и кнопкой, ведущей на отдельный экран.
- **Баг:** процент заполненности захардкожен (`pending ? 80 : 60`) и не зависит от реальных документов.
- `driver_verification_screen.dart`: 4 документа со статусами — логика правильная, но это отдельный экран, а по макету чек-лист встроен в профиль.

## Что сделать
1. **Шапка:** аватар = селфи водителя (если загружено, даже на проверке); если нет — пунктирный круг с иконкой камеры, нажатие запускает съёмку селфи. Имя, телефон, плашка «Не проверен» / «Проверен ✓». Шестерёнка → настройки (язык, уведомления, выход).
2. **Блок «Подтвердите профиль»** прямо в профиле (вынести `_DocSlot` из `driver_verification_screen.dart` в общий виджет):
   - счётчик «N из 4» и сегментный прогресс (4 сегмента: зелёный = approved, серый = pending, пусто = нет/отклонён) — считать из реальных документов;
   - 4 строки со статусами: approved («Подтверждено», зелёный ✓), pending («На проверке»), rejected (красный, причина `rejectReason` + кнопка «Переснять»), none (кнопка «Добавить»);
   - блок скрывается, когда все 4 approved.
3. **Ниже — строки-ссылки:** «Моя машина» (кузов · тонны · допуски) → экран машины; «Куда готов ехать · дом» → экран направлений; «Рейтинг и отзывы» (пусто: «Появятся после первой сделки»); **«Язык · Тіл · 语言 · Language»** (подпись на трёх языках, чтобы найти строку даже на незнакомом языке) → выбор Қазақша / Русский / 中文 / English. Язык не прятать за шестерёнку.
4. **Bottom sheet верификации:** когда сервер отвечает `DRIVER_NOT_VERIFIED` на «Подтверждаю перевозку» (см. 007), открывать тот же чек-лист в bottom sheet, а не переходить на отдельный экран.
5. Отдельный экран `/driver/verification` оставить только как цель для deep link (push об отклонении — в задаче уведомлений).
6. Все строки — ARB (kk/ru/zh/en).

## Правила редактирования (согласовано 2026-10-04)
7. **Имя:** редактируется, пока водитель не verified. После verified поле только для чтения, подсказка «Изменить имя можно через поддержку». Бэкенд тоже запрещает (403).
8. **Телефон:** смена только с подтверждением SMS-кодом на новый номер (`POST /drivers/me/phone/request` → `/verify`, лимиты как у входа). Старый номер освобождается после подтверждения.
9. **Смена машины после верификации:** изменение госномера тягача → VEHICLE_PASSPORT в статус «нужна повторная проверка»; изменение прицепа (госномер прицепа / тип кузова) → TRAILER_PASSPORT в тот же статус. SELFIE и DRIVER_LICENSE не трогаются. `isVerified` пересчитывается → водитель становится не verified до повторной проверки. Перед сохранением показать предупреждение: «После изменения машины нужно заново загрузить техпаспорт».
   Новый статус документа: `RESUBMIT_REQUIRED` (в UI — как «Добавить», с подписью «Машина изменена — загрузите новый техпаспорт»).
10. **Одна машина на водителя** в MVP. Схема `Vehicle` допускает несколько, но API и UI работают с одной; несколько машин — после пилота.

## Готово, когда
- Профиль визуально совпадает с `07-driver-profile.png`.
- Счётчик и прогресс меняются при загрузке/проверке/отклонении документа.
- Отклонённый документ показывает причину от админа и позволяет переснять в один тап.
- Verified-водитель не может сменить имя (ни в UI, ни через API); смена телефона требует кода на новый номер.
- Смена госномера тягача у verified-водителя сбрасывает только техпаспорт тягача и снимает статус «Проверен» (тест).
