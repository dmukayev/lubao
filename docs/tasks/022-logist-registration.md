# 022 — Регистрация логиста и компании

Статус: частично готово (2026-10-04) — Путь А (самостоятельная регистрация
владельца) сделан и проверен целиком; Путь Б (приглашение сотрудника),

## Что сделано (2026-10-04)
- **Путь А — «Создать компанию» целиком**: email → код (reuse `EmailService`
  из задачи 006, те же лимиты, что у SMS) → если email новый, создаётся
  «голый» `User{role: COMPANY}` без компании (как и у водителя — анкета
  донаполняется следующим шагом) → экран «Новая компания»
  (`company_register_screen.dart`): имя владельца, название компании,
  название по-русски (по умолчанию = локальное, можно поправить — реального
  перевода нет, задача 010) → страна кнопками Китай/Казахстан/«Другая»
  (дропдаун на весь список) → `POST /companies/register` создаёт `Company` +
  `CompanyMember{role: OWNER}` в одной транзакции, сохраняет имя в `User.name`
  (новое поле, миграция `company_registration_fields`). Владелец сразу в
  кабинете — `CompanyMemberRole.OWNER` уже имеет все права логиста везде,
  где роль проверяется (отдельных проверок на OWNER/LOGIST в publish/deals
  нет вообще, так что это не требовало доп. кода). Повторная регистрация
  тем же пользователем — 400 (`User is already a member of a company`).
  Роль DRIVER не может дёрнуть эндпоинт — 403.
- Flutter: роутер (`app_router.dart`) редиректит COMPANY-сессию без
  `companyMember` на `/company/register`; после успешной регистрации —
  `sessionProvider.updateCompany(...)`, дальше обычный переход в кабинет.
- Тесты: `companies.service.spec.ts` (4 новых: дубль-членство, неизвестная
  страна, успешная транзакция, фолбэк `nameRu`), `company_register_screen_test.dart`
  (2: успешная регистрация с реальным вводом, пустая страна → инлайн-ошибка).
  Backend-сьют 75/75, `flutter analyze`/`flutter test` чисто во всех трёх
  Flutter-пакетах. Проверено живым curl: email-код для нового адреса →
  `company: null`; `POST /companies/register` → `Company`+`CompanyMember`
  в одной транзакции; повторная попытка → 400; `GET /companies/me` и
  `GET /auth/me` сразу отражают новую компанию; роль DRIVER → 403.

## Сознательно отложено (не выдумано, честно не сделано)
- **Путь Б («У меня приглашение»)** и **п. 12 (админ создаёт компанию →
  письмо-приглашение)** — оба зависят от таблицы `company_invites`, а она
  по тексту самой этой задачи (п. 4) относится к **задаче 012** («Профиль
  компании»), которая не начата. Делать `company_invites` здесь означало бы
  тащить чужую задачу наполовину — решил не трогать.
- **Дубль по рег. номеру (п. 10)** — поле рег. номера появляется в 012
  («Обязательные поля компании»), сейчас у `Company` его нет вообще, так что
  дубликат по нему физически не из чего проверять.
- **Прод email-провайдер для qq.com/163.com и проверка доставки (п. 14-15)**
  — `EmailProvider`-абстракция готова (см. 006), но реальный прод-провайдер
  (Alibaba DirectMail или аналог) не подключён — нет учётных данных, а без
  них это были бы непроверенные заглушки. По тексту задачи это и так
  «до пилота» — оставляю как явный остаток, не прод-провайдер руками.

## Проблема (ревью 2026-10-04)
Регистрации компании нет. Есть только `POST /auth/dev-login/company` (временный вход), компании создаются демо-сидом; админка создать компанию тоже не может. Решения — `docs/decisions.md` (2026-10-04, «Регистрация логиста и компании», «Обязательные поля компании»).

## Что сделать

### Путь А — «Создать компанию» (владелец, ~1 минута)
1. Выбор роли «Я логист» → «Создать компанию» / «У меня приглашение».
2. Email → код на почту (6 цифр, 10 минут, 5 попыток, лимиты как у SMS в 006). Email уже есть — вход. Новый — один экран: имя → компания: название на языке страны, название по-русски (предзаполняется ИИ-переводом — модуль `translation` из 010; пока его нет — транслитерация, можно поправить), страна (кнопками: Китай / Казахстан / Другая) → готово. **Город не спрашиваем** — по желанию позже в профиле компании.
3. Создаются `Company` (не проверена) + `CompanyMember` с ролью **владелец** + сессия (006). Владелец сразу в кабинете: видит водителей, пишет им; баннер «Публикация грузов откроется после проверки» (012).

### Путь Б — «У меня приглашение» (сотрудник)
4. Ссылка из письма (`company_invites`, задача 012) → экран: название компании, кто пригласил → код на email из приглашения подтверждается автоматически по ссылке → имя, телефон для водителей, WeChat (необязательно) → готово, сразу в кабинете этой компании.
5. Просроченное/использованное приглашение — понятное сообщение и «Попросить новое приглашение» (уведомление владельцу).

### Владелец без сотрудников — полноценный логист
6. **Роль «владелец» включает все права логиста**: публиковать грузы, писать и звонить водителям, вести сделки, закрывать грузы. Плюс управление компанией. Многие компании — один человек, приглашать сотрудников не обязательно.
7. Перед первой публикацией у владельца, как у логиста, запрашиваются его телефон для водителей и данные компании (рег. номер, свидетельство) — задача 012.
8. Блок «Сотрудники» для компании из одного человека — компактный: «Работаете не один? Пригласите коллег» (не навязчиво, без обязательного шага).

### Восстановление и дубли
9. ~~«Забыли пароль»~~ — не нужен (вход по коду). Смена email — в «Мой профиль» с кодом на новый email.
10. Дубль компании: при вводе рег. номера (012), если компания с таким номером уже есть — «Компания уже зарегистрирована в Lubao. Попросите владельца пригласить вас» + кнопка «Это моя компания» → заявка админу.
11. Один email — один пользователь; пользователь — в одной компании (MVP).

### Админка
12. «Создать компанию»: название, страна, город, email владельца → письмо-приглашение владельцу (путь Б с ролью «владелец»). Для пилота: вы лично заводите компанию после знакомства.

### Почта (важно для Китая)
13. Провайдер email — абстракция (`EmailProvider`), как SMS. В dev — `ConsoleEmailProvider` (письмо и код в лог, код `111111`).
14. Prod-провайдер должен доставлять в китайские ящики (qq.com, 163.com, 126.com, sina.com) и в Казахстане: рассмотреть Alibaba Cloud DirectMail (основной для Китая) и резервный для остальных. SPF, DKIM, DMARC на домене. Письма — на языке интерфейса пользователя (kk/ru/zh/en), простые, без картинок.
15. Проверка доставки на реальных ящиках qq.com и 163.com — до пилота; результат в `docs/perf/email-delivery.md`.

## Готово, когда
- Новый логист сам создаёт компанию за ~1 минуту и попадает в кабинет.
- Владелец без сотрудников публикует груз (после проверки компании) и ведёт сделку — без приглашения кого-либо.
- Сотрудник по ссылке-приглашению попадает в нужную компанию.
- Вход логиста — только email и код, без пароля; повторная регистрация с тем же рег. номером не создаёт дубль.
- Админ создаёт компанию и владелец получает приглашение.
- Письмо с кодом доходит на qq.com и 163.com (не в спам).
