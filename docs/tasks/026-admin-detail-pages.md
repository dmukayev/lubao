# 026 — Админка: карточки водителя и компании, поиск, блокировка

Статус: готово (2026-10-05)
Эталоны: `design/screens/14-admin-driver.png`, `design/screens/15-admin-company.png`.

## Проблема (ревью 2026-10-04)
- Списки «Водители» и «Компании» — голый `ListTile` с именем, рейтингом и переключателем «проверен». **Провалиться нельзя**: нет маршрутов `/drivers/:id`, `/companies/:id`, нет эндпоинтов `GET /admin/drivers/:id`, `GET /admin/companies/:id`. Админ не видит телефон, машину, направления, документы, анонсы, сделки, сотрудников компании.
- 🔴 **Документы проверяются вслепую.** `verification_screen.dart` показывает только имя и тип документа (`DRIVER_LICENSE`) и кнопки «Одобрить/Отклонить» — **самого фото нет**. `fileUrl` в ответе есть, но не выводится. Тип показывается кодом enum, а не переведённым названием.
- 🔴 **Переключатель «проверен» в списке обходит документы.** Одно случайное касание — водитель «Проверенный» без единого документа (или наоборот, проверенного сбросили). Нет подтверждения, нет записи в `audit_log`. Противоречит решению «Проверенный — только по документам и сделкам в приложении».
- Нет поиска (по имени, телефону, email, госномеру) и фильтров; нет пагинации — при 2000 водителей список встанет.
- Нет блокировки: поле `User.isBlocked` есть и guard его проверяет, но из админки поставить нельзя.
- Жалобы: видно только причину и тип цели — на кого жалоба, не понять, перейти к нарушителю нельзя.

## Что сделать

### Backend (`backend/src/admin`)
1. `GET /admin/drivers?q=&verified=&blocked=&page=&pageSize=` — поиск по `fullName`, `user.phone`, `vehicles.plateNumber` (без учёта регистра, `contains`); ответ `{ items, total }`; в строке: id, имя, телефон, домашний город, кузов + тоннаж, статус проверки, число документов на проверке, рейтинг, сделок завершено, `isBlocked`, дата регистрации, последний анонс (статус + дата).
2. `GET /admin/companies?q=&verified=&blocked=&page=` — поиск по `name`, `nameRu`, `taxId`, email участников; в строке: страна, владелец (имя, email), сотрудников, грузов активных, сделок, проверка, документов на проверке.
3. `GET /admin/drivers/:id` — одним ответом:
   - пользователь: телефон, язык, `createdAt`, `isBlocked`, последний вход (по `Session.lastUsedAt` или `createdAt`);
   - профиль: имя, домашний город (название по локали), направления / «любое», допуски;
   - машина(ы): кузов, тоннаж, длина, госномер, марка;
   - документы: все, со статусом, причиной отклонения, кто и когда проверил, **временная ссылка на файл** (см. п. 6);
   - статистика: сделок по статусам, отмен, рейтинг, отзывы (последние 10), звонков/WhatsApp получено (`contact_events`), жалоб на него и от него;
   - анонсы: последние 20 (точка, `plannedAt`, страны поездки, статус, просмотров);
   - сделки: последние 20 (груз «откуда → куда», компания, статус, дата) — с id компании для перехода;
   - активные сессии (устройство/платформа, последняя активность);
   - журнал: последние 30 записей `audit_log` по этому пользователю/водителю.
4. `GET /admin/companies/:id` — компания (название, по-русски, страна, город, юр. адрес, рег. номер/`taxId`), проверка (документы как у водителя), сотрудники (имя, email, роль, последний вход), приглашения (email, роль, истекает/использовано), грузы последние 20 (маршрут, цена+валюта, статус, откликов), сделки последние 20 (водитель с id, статус), рейтинг и отзывы, жалобы, журнал.
5. Действия (все — с записью в `audit_log`: кто, что, причина):
   - `POST /admin/users/:userId/block { reason }` / `.../unblock` — `isBlocked`, при блокировке `sessions.revokeAllForUser`; блокировка компании = блок всех её участников + скрыть её активные грузы из ленты (статус груза не трогать, фильтровать по `isBlocked` владельца/компании). Причина обязательна.
   - `PATCH /admin/drivers/:id/verify` и `/companies/:id/verify` — **оставить, но** требовать `{ isVerified, reason }`; при `true` — только если все обязательные документы `APPROVED` (иначе 400 с перечнем недостающих), либо явный флаг `force: true` с причиной (для пилота: «проверил лично»). Писать в `audit_log`.
   - «Сбросить пароль» владельцу (эндпоинт есть, `resetCompanyPassword`) — вывести кнопку в карточке компании, временный пароль показать один раз в диалоге с кнопкой «Скопировать»; писать в `audit_log`.
   - «Завершить все сессии» пользователя.
   - Сейчас `isBlocked` проверяет только `JwtAuthGuard`; вход (SMS-код, email+пароль) и `/auth/refresh` его не проверяют — заблокированный получает токены и сразу 401. Проверять при входе и refresh, отвечать 403 с кодом `ACCOUNT_BLOCKED`, в приложении — экран «Аккаунт заблокирован, свяжитесь с поддержкой» (без бесконечного цикла входа).
6. Файлы документов: бакет MinIO **приватный**; админ получает presigned GET на 10 минут, генерирует бэкенд в п. 3/4 и в очереди проверки. Публичных ссылок на документы не делать (персональные данные).
7. Жалобы: в ответе `GET /admin/complaints` добавить `target` — `{ type, id, title, driverId?, companyId? }` (для CARGO/DEAL/CHAT_MESSAGE — владелец/участник, на кого фактически жалоба), чтобы из жалобы был переход в карточку.
8. Ответы — без `passwordHash` и хешей токенов (`select`, не `include: true` — как уже сделано в `pendingCities`). Тест на это.

### Админка (`apps/lubao_admin`)

10. Списки → таблица на всю ширину (макеты 14/15 — слева меню, как сейчас): поиск сверху, чипы-фильтры «Все / На проверке / Проверенные / Заблокированные», колонки из п. 1/2, пагинация по 50. **Переключатель «проверен» из строки убрать** — клик по строке открывает карточку.

    - шапка: аватар-инициалы, имя, бейдж «Проверен»/«Не проверен»/«Заблокирован», телефон (копировать), город, «с нами с …», последний вход; справа — «Заблокировать» (красная обводка) и меню «⋯» (завершить сессии, снять/поставить проверку с причиной);

    - слева: **Документы** — превью фото (клик → просмотр на весь экран с зумом и поворотом), статус, кнопки «Одобрить»/«Отклонить» прямо здесь; **Машина**; **Направления и допуски**;
    - справа: вкладки «Анонсы · Сделки · Отзывы · Жалобы · Журнал»; в сделке — переход в карточку компании.
12. **Карточка компании** (макет 15): шапка (название + по-русски, страна, рег. номер, бейджи), строка цифр (грузов активных, сделок, сотрудников, рейтинг, жалоб), слева — документы проверки и реквизиты, сотрудники с ролями и приглашениями; справа — вкладки «Грузы · Сделки · Отзывы · Жалобы · Журнал»; кнопки «Заблокировать компанию», «⋯» → «Сбросить пароль владельцу», «Снять проверку».
13. **Очередь проверки**: показывать превью файла и переведённое название типа; имя — ссылка в карточку (там видно весь комплект документов разом — проверять удобнее там). Отклонение — причина из готовых вариантов («Нечитаемое фото», «Документ просрочен», «Не совпадает имя», «Другое…») + свободный текст.
14. **Жалобы**: показывать, на кого жалоба и кто пожаловался, обе стороны — ссылки в карточки.
15. Строки — только ARB (kk/ru/zh, en — после 013); статусы и типы документов — через l10n, не коды enum. Админка по-русски по умолчанию, но без захардкоженных строк.
16. Все опасные действия (блок, снять проверку, сброс пароля) — диалог подтверждения с полем причины.

## Готово, когда
- Из списка водителей/компаний клик открывает карточку; адрес `/drivers/<id>` открывается напрямую после перезагрузки страницы.
- Поиск по части телефона, госномеру, email и названию компании находит нужную запись; на 2000 демо-водителей список открывается < 1 с (пагинация).

- Поставить «Проверен» без одобренных документов нельзя без `force` и причины; каждое изменение проверки, блок, сброс пароля видны в журнале карточки.
- Заблокированный водитель выкинут из приложения (сессии отозваны), повторный вход → понятное сообщение «Аккаунт заблокирован»; грузы заблокированной компании не видны водителям.

- В ответах admin API нет `passwordHash`/хешей токенов (тест).
- Тесты backend: поиск, детали, блок/разблок с отзывом сессий, verify без документов → 400, audit_log пишется. `flutter analyze`/`flutter test` чисто.

## Что сделано (2026-10-05)

### Backend
Всё из п. 1–8 реализовано в `admin.service.ts`/`admin.controller.ts`:
- `searchDrivers`/`searchCompanies` — `{items, total}`, регистронезависимый поиск (`contains`/`insensitive`) по полям из п. 1/2, фильтры `verified`/`blocked`, пагинация 50/стр (`SearchQueryDto`).
- `driverDetail`/`companyDetail` — полный вложенный ответ: пользователь, профиль, машины, документы (с presigned-ссылкой через `UploadsService.presignDocumentUrl`), статистика (сделки по статусам, отмены, рейтинг, 10 отзывов, звонки/WhatsApp, жалобы), анонсы/грузы/сделки (20 последних), активные сессии, 30 записей `audit_log`.
- `blockUser`/`unblockUser`, `blockCompany`/`unblockCompany` (блокирует компанию + всех сотрудников + отзывает их сессии, транзакция), `revokeSessions` — всё пишет в `audit_log` (`actorUserId`, `action`, `entityType`, `entityId`, `metadata.reason`).
- `setDriverVerified`/`setCompanyVerified` — `reason` обязателен; `isVerified: true` без `force` при неодобренных обязательных документах → 400; `force: true` + причина обходит проверку («проверил лично»); тоже в `audit_log`.
- `resetCompanyPassword` — та же логика, что и раньше, плюс запись в `audit_log` (раньше её не было).
- `complaints()`/`resolveComplaint()` переведены на `select` (не `include: true`) — тест подтверждает отсутствие `passwordHash` в выборке. Добавлены `target` и `reporter` — оба резолвятся через один и тот же `complaintTarget(type, id)` (для `USER` — ищет driverId/companyId через `driver`/`companyMember`), что даёт переход и к нарушителю, и к заявителю.
- MinIO: бакет документов приватный, `presignDocumentUrl` отдаёт подписанную ссылку на 10 минут; легаси-документы с уже готовым `https://` URL (демо-сид) проходят как есть.
- `cargos.service.ts#feed()`: добавлен фильтр `company: { isBlocked: false }` — статус груза не трогается, просто скрывается из ленты.
- Вход (SMS-код, email+пароль логиста) и `/auth/refresh` проверяют `isBlocked` — 403 `{code: 'ACCOUNT_BLOCKED'}` вместо выдачи токенов с последующим молчаливым 401 (см. также 013/024 — часть этой работы была сделана параллельно, не задним числом).
- Тесты: 24 новых в `admin.service.spec.ts` (поиск/фильтры/пагинация, детали + presign, блок/разблок + отзыв сессий, force-гейт верификации, сброс пароля, select-без-passwordHash, резолв target/reporter) + 1 в новом `cargos.service.spec.ts`. Backend-сьют — 146/146.
- Живая проверка на реальных demo-данных (`seed-demo.ts`) через curl: поиск, детали водителя/компании с реальными документами (включая легаси `placehold.co`-ссылки), verify без force → 400 → с force → 200, блокировка → попытка SMS-входа → `ACCOUNT_BLOCKED` → разблокировка, жалоба → `target`/`reporter` с рабочими `driverId`/`companyId`.

### Админка (apps/lubao_admin)
- Маршруты `/drivers/:id`, `/companies/:id` внутри `ShellRoute` — прямой заход по URL работает (проверено статически через конфигурацию `go_router`, тип `path parameters`).
- Списки водителей/компаний — таблица (`DataTable`) с поиском (debounce 350 мс), чипами «Все/На проверке/Проверенные/Заблокированные», пагинацией; переключатель «проверен» из строки убран, клик по строке — переход в карточку.
- Карточка водителя/компании: шапка (бейдж статуса, телефон с копированием, даты), строка статистики, документы с превью (клик → полноэкранный просмотр с зумом `InteractiveViewer` и поворотом на 90°, без новой зависимости), «Заблокировать»/«Разблокировать», меню «⋯» (завершить сессии / изменить статус проверки — водитель; сбросить пароль / изменить статус проверки — компания), вкладки с данными (сделки, отзывы, журнал — водитель; грузы, сделки, отзывы, журнал — компания). Все опасные действия — диалог с обязательной причиной (`showReasonDialog`/`showVerifyDialog`).
- Очередь проверки (`verification_screen.dart`): превью фото, переведённое название типа документа, имя — ссылка в карточку.
- Причины отклонения — пресеты («Нечитаемое фото», «Документ просрочен», «Не совпадает имя») + свободный текст (`showRejectReasonDialog`).
- Жалобы: заявитель и объект жалобы — оба ссылки в карточки (используют `target`/`reporter` с бэкенда).
- Все новые строки — в ARB (`ru`/`kk`/`zh`/`en` — английский не был в изначальном скоупе задачи, но раз 013 уже сделана, страниц без него не оставлял).
- `flutter analyze`/`flutter test` чисто во всех трёх Flutter-проектах (lubao_core 28/28, lubao_app 20/20, lubao_admin 1/1). Заодно найден и исправлен баг, внесённый в 013: `I18nText.forLanguageCode('en')` не имел ветки `en` вообще (падал в `ru`) — названия справочников на английском не отображались бы.

### Сознательные упрощения (не делал, чтобы не раздувать и так крупную задачу)
- Вкладка карточки водителя «Анонсы» не отрисована отдельным списком (бэкенд отдаёт последние 20 анонсов, но Flutter-модель/UI их не разбирает) — оставлены 3 вкладки (Сделки/Отзывы/Журнал) вместо 5 из макета; жалобы показаны счётчиком в строке статистики, а не отдельной вкладкой-списком (на человека нет готового списка жалоб с пагинацией, только `count`).

- Я проверил новую админку статическим анализом, автотестами и живыми curl-запросами к бэкенду; визуально в браузере не прошёлся — скриншот через `screencapture` в этом окружении стабильно цеплял рабочий стол пользователя, а не окно Chrome. Дев-сервер оставлен запущенным на `localhost:5566` для ручной проверки.
