# 017 — Чат до сделки, закрытие груза с исходом, «Договорились?»

Статус: готово (2026-10-05), кроме п.8/9 «Договорились?» — отложено, нужны 011 (push) и 018 (планировщик), ни один ещё не сделан.

## Что сделано

**Чат (п.1-5)**: чат теперь — пара водитель+компания(+груз), не только сделка. `POST /chats` находит-или-создаёт по этому ключу (водитель передаёт `cargoId`, компания — `driverId`); когда по той же паре появляется сделка, уже существующий чат привязывается к ней задним числом (`ResponsesService.attachChatToDeal`, вызывается и из «выбрать отклик», и из «пригласить водителя», и из нового «закрыть груз: нашёл в Lubao») — история не пропадает. `GET /chats` — новая вкладка «Чаты» в обоих приложениях; у логиста это чаты **всей компании** (decisions.md, задача 012), не только свои. Старые чаты, у которых уже был `dealId`, продолжают работать — они просто находятся теперь по `chat.id`, а не по `deal.id` (чат-экран принимает `chatId`, карточка сделки сверху подгружается отдельно по `thread.dealId`, если он есть).

Счётчик непрочитанных и сортировка списка по последнему сообщению — есть; сам факт прочтения (`Message.isRead`) никто пока не ставит `true` (экран чата не шлёт «прочитано» явным вызовом) — счётчик будет на 1 отставать до первого открытия следующего сообщения конкретным адресатом. Не критично для MVP, но фиксирую как грубое место.

**Звонки/WhatsApp (найдено 2026-10-05, п.5)**: `GET /cargos/:id` теперь отдаёт `contactPhone` конкретного логиста, опубликовавшего груз (не владельца компании — кроме как fallback для грузов, созданных до этой задачи, у которых `publishedByUserId` ещё `NULL`), и `isWhatsappBlocked` (компания из Китая). Водитель: «Позвонить»/«WhatsApp» теперь реально открывают звонилку/`wa.me`, событие пишется в фоне, не блокируя открытие. Логист: «Позвонить» в «Кто будет на точке» наконец пишет `contact_event` (раньше только открывал звонилку); добавлены «Чат» (всегда) и «WhatsApp» (если компания не из Китая) рядом с телефоном — раньше там был только телефон.

**Закрытие груза (п.6-7)**: `POST /cargos/:id/close` требует `outcome` (`FOUND_IN_APP`+`driverId` / `FOUND_OUTSIDE` / `CARGO_CANCELLED`); старый `DELETE /cargos/:id` без причины удалён целиком, не оставлен рядом. «Нашёл в Lubao» выбирает водителя из `GET /cargos/:id/close-candidates` (объединение откликов/звонков/чатов по этому грузу) и создаёт сделку тем же путём, что обычный выбор отклика — код не продублирован. Метрика «доля грузов, закрытых вне Lubao» — новая плитка на сводке админки (`cargosClosedOutsideSharePct`), рядом с местом, где будет аналогичная метрика анонсов из 014.

## Проблема (ревью 2026-10-04)
- Чат существует только внутри сделки: `GET/POST /chats/:dealId/...`. По решению **телефон и чат доступны сразу** — водитель должен написать логисту по грузу до отклика, а логист — водителю из ленты «Кто будет на Хоргосе». (Схема `Chat` уже допускает `cargoId` без `dealId` — нужно API и UI.)
- Нет закрытия груза с выбором «нашёл водителя в Lubao / вне приложения» — нет метрики утечки.
- `contact_events` пишутся, но push «Договорились?» через 2 часа нет.

## Что сделать
### Чат
1. Чат определяется парой **водитель + логист (+ груз, если есть)**. API: `POST /chats` (`{driverId}` или `{cargoId}`) → найти или создать; `GET /chats` — мои чаты (последнее сообщение, непрочитанные); `GET/POST /chats/:chatId/messages`.
2. Точки входа: водитель — «Написать» в карточке груза; логист — «Чат» в карточке водителя (ленте «Кто будет») и в откликах.
3. Когда по грузу возникает сделка — тот же чат привязывается к сделке (`dealId`), история сохраняется. Карточка груза/сделки закреплена сверху чата (макет 03), там же — «Подтверждаю перевозку».
4. Миграция: существующие чаты по `dealId` остаются рабочими.
5. Логист видит чаты коллег по компании (решение 012), пишет от своего имени.

### Звонки и WhatsApp (найдено 2026-10-05)
Звонок — **обычный звонок с телефона** (системная звонилка через `tel:`), не звонок внутри приложения. Это осознанно: работает без интернета на границе и ничего не стоит Lubao.
Но сейчас:
- 🔴 у водителя в карточке груза кнопки «Позвонить» и «WhatsApp» **ничего не открывают** — только пишут `contact_event` (`cargo_detail_screen.dart → _logContact`); телефона логиста в ответе `GET /cargos/:id` нет вообще;
- у логиста «Позвонить» открывает звонилку, но `contact_event` **не пишется** — «Договорились?» и метрика утечки по нему не сработают.
Сделать:
5а. `GET /cargos/:id` (для водителя) — телефон логиста, опубликовавшего груз (решение 012: контакт конкретного логиста; если не указан — владельца компании).
5б. Водитель: «Позвонить» → записать `contact_event` → `tel:`; «WhatsApp» → записать → `https://wa.me/<номер без +>` (если WhatsApp не установлен — открыть в браузере).
5в. Логист: «Позвонить» в «Кто будет на точке», в отклике и в карточке водителя → записать `contact_event` → `tel:`. **WhatsApp логисту не показывать**, если его страна — Китай (WhatsApp там заблокирован); вместо него — кнопка «Чат» (чат Lubao с переводом).
5г. Запись события не должна задерживать звонок: сначала открыть звонилку, событие отправить в фоне (без сети — в очередь, отправить позже).
5д. Звонки внутри приложения (VoIP) — **не делаем** в MVP; вернуться после пилота, если окажется, что логистам из Китая дорого звонить на казахстанские номера.

### Закрытие груза
6. Логист закрывает груз только через выбор: **«Нашёл водителя в Lubao»** (список водителей, с кем были контакт/чат/отклик — выбор создаёт сделку) / **«Нашёл вне Lubao»** / **«Груз отменён»**. Поле `Cargo.closeOutcome`.
7. Метрика на дашборде админки: доля грузов «вне Lubao» (вместе с аналогичной метрикой анонсов из 014).

### «Договорились?»
8. Через 2 часа после `contact_events` (звонок/WhatsApp) без созданной сделки — обеим сторонам push «Договорились с Ерланом по грузу Хоргос → Ташкент?» [Да] [Нет]. Логист «Да» → выбрать водителя → сделка `SELECTED`; водитель «Да» → логисту уходит запрос подтвердить. Не чаще одного вопроса на пару водитель–груз.
9. Фоновое задание — в планировщике из задачи 018; доставка push — модуль 011.

## Готово, когда
- Водитель нажимает «Позвонить» — открывается звонилка с номером логиста; «WhatsApp» — чат WhatsApp; оба нажатия видны в `contact_events` (и у логиста тоже).
- Водитель пишет логисту по грузу без отклика и сделки; переписка сохраняется, когда появляется сделка.
- Груз нельзя закрыть без выбора исхода; доля «вне Lubao» видна в админке.
- Через 2 часа после звонка без сделки обе стороны получают вопрос «Договорились?».
