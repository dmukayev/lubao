# 074 — «Что-то пошло не так» → настоящая причина ошибки везде

Статус: **готово** (2026-10-13).
- п.1: бэкенд — общий `ErrorCodeFilter`: у каждого ответа-ошибки `code` и короткий `requestId`; свой код остаётся, текст-код (`POINT_REQUIRED`) → он, частые тексты («Cargo not found» → `CARGO_NOT_FOUND` и т. п.) — по таблице в `common/error-codes.ts`, иначе — по статусу; 5xx наружу без подробностей, в журнал и Sentry — с номером. Тест-сторож: каждый код в `throw … Exception({ code })` есть в списке для перевода.
- п.2: `apiErrorText` (lubao_core): нет сети / таймаут → код сервера → вид ответа (401, 403, 404, 409, 413, 429, 5xx) → «Что-то пошло не так · ошибка <номер>». `errorMessage` приложения — поверх неё (ошибки полей 072 и конфликты откликов — своим разбором); `contactErrorText` и тексты входа (073) влиты.
- п.3: все 77 прямых `commonError` (приложение и админка) заменены на текст по настоящей ошибке.
- п.4: ARB — тексты для 102 кодов и «Нет интернета», «Сервер долго не отвечает», «Что-то пошло не так · ошибка {id}», 4 языка.
- п.5: CI — `error_codes_arb_test.dart`: каждый код из `error-codes.ts` имеет текст на ru/kk/zh/en; `t.commonError` напрямую — только в общих функциях.
- п.6: админка — то же.
- п.7: e2e `error_messages` — нет сети → «Нет интернета», груза нет → «Груз не найден», два логиста выбирают одного водителя → «отклик уже рассмотрен».
- Проверка: полный `scripts/e2e.sh` — все сценарии зелёные на iPhone SE и Android 360 + Chrome (`evidence/074/e2e-full-run.md`).
Откуда: владелец 2026-10-13 — «“Что-то пошло не так” точно везде исправлено на реальную ошибку?». Нет: `commonError` используется в 79 местах на 46 экранах (приложение и админка). Понятные тексты есть только у «Позвонить» (`contactErrorText`) и частично у входа (073).
Оценка: 1 день.

## Что сделать
1. **Бэкенд — у каждой ошибки код:**
   - пройти все `throw new …Exception(...)` в `backend/src`: у каждой ошибки, которую может увидеть пользователь, — `{ code, message }` (например, `CARGO_NOT_FOUND`, `CARGO_ALREADY_TAKEN`, `DEAL_WRONG_STATUS`, `FILE_TOO_LARGE`, `NOT_COMPANY_MEMBER`);
   - список кодов собрать в одном файле (`common/error-codes.ts`).
2. **Приложение — одна функция `errorMessage(t, e)`** в `lubao_core`. Порядок:
   1. известный `code` → свой текст из ARB;
   2. ошибки проверки полей (`violations`) → у поля (072);
   3. по виду ошибки:
      - нет сети → «Нет интернета. Проверьте связь и повторите»;
      - таймаут → «Сервер долго не отвечает. Повторите»;
      - 401 → «Сессия закончилась, войдите снова» и переход на вход;
      - 403 → «Нет доступа»;
      - 404 → «Не найдено — возможно, уже удалено»;
      - 409 → «Уже изменено другим пользователем — обновите»;
      - 413 → «Файл слишком большой (до N МБ)»;
      - 429 → «Слишком часто, подождите минуту»;
      - 5xx → «Сервер временно недоступен, попробуйте позже»;
   4. только если ничего не подошло — «Что-то пошло не так» и **короткий номер ошибки** (request id из ответа), чтобы назвать его поддержке.
3. **Заменить все 79 прямых `t.commonError`** на `errorMessage(t, e)`. `contactErrorText` и тексты входа (073) влить в общую функцию.
4. **ARB:** тексты для всех кодов, 4 языка.
5. **Проверка в CI (обязательная):**
   - тест: каждый код из `error-codes.ts` имеет текст в ARB на всех 4 языках;
   - `grep -rn "t.commonError" apps packages` — только внутри `errorMessage`.
6. **Админка** — то же.
7. **e2e:**
   - выключить сеть → «Нет интернета»;
   - груз уже снят → «Не найдено»;
   - два логиста выбирают одного водителя → понятная причина.

## Готово, когда
- «Что-то пошло не так» появляется только при действительно неизвестной ошибке и с номером ошибки.
- CI-проверка из п.5 зелёная.
- `scripts/e2e.sh` зелёный на iPhone SE и Android 360 (крупный шрифт) + админка в Chrome.
