# 005 — Профиль водителя и верификация

Статус: не начато

## Цель
Водитель подтверждает личность и машину из профиля; админ проверяет документы; логист видит, кто проверен.

Эталон: `design/screens/07-driver-profile.png`. Причины решения — `docs/decisions.md` (2026-10-04).

## Flutter — профиль водителя
1. Шапка: фото (пока нет — пунктирный круг с камерой), имя, телефон, плашка «Не проверен» / «Проверен ✓».
2. Блок «Подтвердите профиль» — чек-лист из 4 документов, прогресс «N из 4». Исчезает, когда все approved.
   - `selfie` — только камера (галерея запрещена), рамка-овал.
   - `vehicle_registration_tractor` — техпаспорт тягача, обе стороны.
   - `vehicle_registration_trailer` — техпаспорт прицепа, обе стороны.
   - `driver_license` — лицевая сторона.
3. Статусы справа: approved (зелёный ✓) / pending («На проверке») / rejected (красный, причина + «Переснять») / none («Добавить»).
4. Ниже: «Моя машина», «Куда готов ехать · дом» (открывают экраны из 004 в режиме редактирования), «Рейтинг и отзывы».
5. Без verified кнопка «Подтверждаю перевозку» открывает этот же чек-лист в bottom sheet.

## Бэкенд
6. Загрузка фото в MinIO, сжатие до 1600 px по длинной стороне. Доступ к файлам — только по подписанным ссылкам.
7. `verification_documents`: каждый документ — своя запись и свой статус. `driver.verified` = все 4 approved (пересчёт при каждом изменении).
8. При rejected — push водителю с причиной и deep link на нужный пункт.

## Админка
9. Очередь «На проверке»: фото документа + селфи рядом, кнопки «Подтвердить» / «Отклонить» с выбором причины (размыто, не тот документ, данные не читаются, другое).

## НЕ делать
Автоматическое распознавание документов — после пилота.

## Готово, когда
- Водитель загружает документы по одному и видит статусы.
- Админ подтверждает/отклоняет, водитель получает push.
- После 4 approved плашка меняется на «Проверен ✓», логист видит ✓ в ленте.
- Без verified подтвердить сделку нельзя (проверка и на бэкенде).
