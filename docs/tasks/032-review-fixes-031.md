## 🔴 Блокеры

### 1. OCR не работает на реальных загрузках + SSRF
`backend/src/…/ocr-client.ts:21` отправляет в OCR `fileUrl`, а у новых документов это **ключ объекта** MinIO (`uploads.service.ts:94`), не URL → `infra/ocr/server.py:38` `requests.get("uuid.jpg")` падает → всегда `SKIPPED`. Плюс `fileUrl` задаёт клиент (`@IsString`) → OCR-контейнер скачивает любой адрес (SSRF во внутреннюю сеть).
Исправить: бэкенд сам читает байты из приватного бакета (`uploads.service`) и шлёт в OCR **multipart** (`POST /recognize` с файлом); `server.py` принимает только файл, никаких URL; лимит размера (10 МБ) и проверка типа (jpeg/png/heic→jpeg). `fileUrl` от клиента принимать только как ключ из нашего же `POST /uploads/document` (проверять, что объект существует в бакете документов и загружен этим пользователем).

### 2. Чёрный список обходится обычной кнопкой «Подтвердить»
`apps/lubao_admin/…/verification_screen.dart:262-272` игнорирует `blacklistHit`; `admin.service.ts:2136-2157` (`setDriverVerified`) чёрный список не проверяет; `:871-917` считает совпадение только по текущему документу (одобрили права с ⛔-ИИН, потом селфи — проверен).
Исправить: **на сервере** `setDriverVerified/setCompanyVerified/approve vehicle` перед подтверждением проверяют **все** подтверждённые и распознанные идентификаторы субъекта по `blocked_identifiers`; при совпадении — 409 `BLACKLIST_MATCH` (с перечнем), подтверждение только с `force: true` + `reason`, запись в `audit_log`. В UI при ⛔ кнопка «Подтвердить» неактивна, вместо неё «Подтвердить вопреки чёрному списку…» с причиной.

### 3. Принятые без правки поля не сохраняются в идентификаторы
`verification_screen.dart:155,232,270` — в `confirmedFields` уходят только поля, которые админ **изменил**; согласился с распознанным ИИН — он не попадает в `identifiers`, блокировка по ИИН потом ничего не найдёт. То же для ранее одобренных документов (отфильтрованы в `toApprove`).
Исправить: при подтверждении отправлять **все** распознанные поля документа (с флагом `editedByAdmin`), сервер сохраняет их в `identifiers`; для уже одобренных документов — тоже (идемпотентно, upsert по `(type, valueHash, ownerId)`).

### 4. ИИН хранится и отдаётся открытым текстом
- `recognition.service.ts:79` — `document_recognitions.fields` хранит ИИН и номер прав **в открытом виде** бессрочно → хранить в `fields` только маску + `valueHash`, полное значение — зашифрованным (тем же `IDENTIFIER_KEY`), или удалять сырые значения после подтверждения документа;
- `admin.service.ts:803-811` — `GET …/recognition` отдаёт полный ИИН без кнопки «Показать» и без журнала → отдавать маску; полное — через тот же reveal-эндпоинт с `audit_log`;
- `admin.service.ts:847-853` — `audit_log` (`DOCUMENT_FIELD_CORRECTED`) пишет полные `recognized/corrected` → в журнал только маски.

### 5. Сделка проверяет не ту связку машин
`responses.service.ts:63-71` записывает в сделку **первые по дате** тягач и прицеп из гаража, а не связку из анонса водителя. Проверенный тягач A в гараже, в анонсе выбран непроверенный B → подтверждение проходит по A, логист видит B.
Исправить: связка сделки = связка активного анонса водителя (если анонса нет — водитель выбирает при подтверждении). `deals.service.ts:112-113`: если связки нет или в ней нет тягача — **не пропускать**, а отвечать 409 `VEHICLE_REQUIRED`; проверять тягач и (если не RIGID) прицеп.

### 6. Правка водителя в админке стирает госномер тягача
`driver_edit_panel.dart:48-59` берёт поля из **первой** машины списка; порядок не задан (`admin.service.ts:1690`, без `orderBy`), у пары после миграции одинаковый `createdAt` → если первым пришёл прицеп (госномер NULL), форма шлёт `''` → `admin.service.ts:2272-2290` пишет пустой госномер тягачу, снимает «проверен», отправляет техпаспорт на перепроверку — даже если админ правил только имя.
Исправить: в панели — отдельные блоки по каждой машине гаража (тягачи/прицепы), отправлять **только изменённые** поля и с `vehicleId`; сервер игнорирует неизменённые и пустые значения не пишет поверх существующих без явного «очистить». `orderBy: [{kind:'asc'},{createdAt:'asc'}]` везде, где список машин.
