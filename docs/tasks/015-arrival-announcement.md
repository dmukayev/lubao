# 015 — Анонс прибытия заранее (ядро продукта)

Статус: готово (2026-10-04)

## Что сделано (2026-10-04)
- **Данные**: `Arrival` получил `plannedAt` (дата/время, до +14 дней), `waitDays`

  отличие от старого кода, который ошибочно читал профиль). Новая
  `ArrivalView` — уникальные компании, которые увидели анонс (счётчик
  «N логистов посмотрели»). Статусы: `PLANNED → ON_SITE → COMPLETED` /
  `CANCELLED`. Новая таблица `app_settings` (ключ-значение) +
  `defaultPointCityId` — нигде в коде не упоминается «Хоргос» текстом.
- **Один активный анонс на водителя**: `announce()` обновляет существующий
  PLANNED на месте (не плодит дубли); если водитель уже `ON_SITE`, точка и
  дата не трогаются — меняются только страны/срок ожидания на эту поездку.
- **Истечение**: PLANNED, чей `plannedAt` в прошлом больше 24 ч, сам
  становится `CANCELLED` — ленивая проверка при каждом чтении (`getMine`,
  `listForCompany`, `summary`), а не отдельный cron. Честно: полноценный
  фоновый джоб с фиксированным интервалом — задача **018**, здесь она не
  начиналась; ленивая проверка — рабочий, протестированный эквивалент для
  текущего масштаба.
- **Водитель — 3 нажатия** (`announce_arrival_sheet.dart`): когда
  (Сегодня/Завтра/Послезавтра/выбрать дату) → где (точка, пока одна —
  Хоргос, т.к. терминалы по отдельности это задача 008) → куда готов
  (страны этой поездки, по умолчанию — из профиля) → «Опубликовать».
  «Повторить прошлый анонс» — одной кнопкой на основе последнего
  завершённого/отменённого анонса (`GET /arrivals/last-template`).
  Карточка анонса показывает счётчик просмотров, «Я уже на месте» (пока
  `PLANNED`), «Изменить», «Отменить».
- **Логист — полоса из 7 дней** (`drivers_at_point_screen.dart`): чипы
  дней со счётчиком (`GET /arrivals/summary`), выбор дня фильтрует список.
  «Сегодня» = `ON_SITE` (независимо от того, что `plannedAt` мог быть
  другим днём) + `PLANNED` на сегодня; остальные дни — только `PLANNED`
  на этот день. Фильтр по стране — по направлениям **этой поездки**
  (`ArrivalDirection`), не по профилю (п. 12 задачи — явный баг старого
  кода, исправлен).
- Тесты: `arrivals.service.spec.ts` (18 новых — announce replace/preserve
  ON_SITE, 14-дневный лимит, checkIn оба пути, repeat, ленивое истечение,
  фильтрация по дню/точке/стране именно по поездке, подсчёт просмотров,

  `announce_arrival_sheet_test.dart` (3 нажатия → announce с нужными
  параметрами; «Любая страна» очищает страны), `flutter analyze`/`flutter
  test` чисто во всех трёх пакетах. Живой curl: анонс на завтра в UZ →
  не виден логисту сегодня, виден завтра и под фильтром UZ, не виден под

  (включая починенный баг двойного счёта); `cancel` → `COMPLETED`/

## Сознательно не делал (не выдумано, честно отложено)
- **Геозона для автоперехода `PLANNED → ON_SITE`** (п. 3) — зависит от
  геолокации, задача **008**, не начата. Переход только кнопкой «Я уже
  на месте».
- **Push «Вы доехали?»** при истечении анонса (п. 4) — зависит от задачи
  **011** (push-уведомления), не начата. Анонс просто тихо переходит в
  `CANCELLED`.
- **Несколько терминалов на точке** (МЦПС/Восточные ворота/Нуркент/Нур
  Жолы, п. «Где») — явно задача **008**; сейчас у Хоргоса в сиде одна
  точка, выбор точки в анонсе — честный dropdown на один вариант, код не
  хардкодит это допущение (расширится само, когда 008 добавит точки).
- **Полноценный фоновый cron для истечения** — задача **018**; ленивая
  проверка на чтении — рабочий эквивалент, покрытый тестами.
- **Админ-UI для `app_settings`** — эндпоинты (`GET/PATCH
  /admin/settings/:key`) готовы и протестированы, экран в `lubao_admin` не
  делал: при единственной активной точке это пока не даёт практической
  пользы (сам текст задачи: «пока активная точка одна — выбор города не
  показывать»).

## Проблема (ревью 2026-10-04)
Главная идея Lubao — водитель **заранее** сообщает, когда будет на точке, а логист видит «кто будет на Хоргосе завтра, послезавтра». В коде этого нет:
- `arrivals.service.ts → checkIn()` создаёт анонс только «сейчас» (`arrivedAt = new Date()`) и берёт **первую активную точку** (`point.findFirst`), а не выбранную водителем;
- нет даты/времени будущего прибытия, нет стран на конкретную поездку;
- у логиста нет полосы дней (макет 06) — показать «завтра 18 водителей» не из чего.

## Что сделать

### Данные
1. `Arrival`: `plannedAt` (дата и время прибытия, можно в будущем, до +14 дней), `pointId` (выбранный терминал, задача 008), `tripCountryIds` (страны на эту поездку; по умолчанию — из профиля, `anyCountry` — флаг), `waitDays` (1/2/3 — см. 014), `arrivedAt?` (фактическое прибытие).
2. Статусы: `PLANNED` (буду) → `ON_SITE` (на месте) → `FOUND_CARGO` / `COMPLETED` / `CANCELLED` (+ статусы из 014). Один активный анонс на водителя.
3. Переход `PLANNED → ON_SITE`: кнопка «Я уже на месте» или геозона терминала (008).
4. `PLANNED`, у которого `plannedAt` прошёл больше чем на 24 ч без перехода в `ON_SITE` → `CANCELLED` (push «Вы доехали до Хоргоса? [Да, я на месте] [Не приеду]»).

### Водитель — анонс в 3 нажатия (главная, макет 01)
5. Нет активного анонса → большая кнопка **«Буду на Хоргосе»** → bottom sheet:
   1) **Когда:** «Сегодня / Завтра / Послезавтра / Выбрать дату» + время (необязательно, «в течение дня»);
   2) **Где:** терминал (МЦПС / Восточные ворота / Нуркент / Нур Жолы), по умолчанию — последний использованный;
   3) **Куда готов:** страны из профиля уже отмечены, можно изменить на эту поездку.
   → «Опубликовать». Плюс «Сколько готовы ждать» (014) — по умолчанию 2 дня.
6. **«Повторить прошлый анонс»** — одна кнопка: те же терминал и страны, дата — сегодня/завтра.
7. Активный анонс — синяя карточка (макет 01): терминал, дата/время или «на месте», страны, счётчик «N логистов посмотрели», кнопка «Я уже на месте» (если PLANNED), «Изменить», «Отменить».
8. Счётчик просмотров: `arrival_views` (arrival_id, company_id, дата) — уникальные компании.

### Точка по умолчанию (решение 2026-10-04)
- `app_settings` (ключ–значение, редактируется в админке): `defaultPointCityId` = город «Хоргос» из справочника.
- Логист («Кто будет»), водитель (анонс), публикация груза, лента грузов: по умолчанию выбран этот город (все его терминалы).
- Пока активный город с точками один — выбор города не показывать, только терминалы. Когда станет больше — запоминать последний выбор пользователя (на сервере, в профиле), новому — из настройки.
- В коде и текстах «Хоргос» не упоминается — только через справочник/настройку.

### Логист — «Кто будет на точке» (макет 06)
9. API `GET /arrivals?from=&to=&pointId=&cityId=&countryId=&bodyTypeId=&minTons=&verifiedOnly=` + `GET /arrivals/summary?days=7` → число водителей по дням.
10. Полоса из 7 дней: «Сегодня · 12», «Пн · 18»…; выбранный день фильтрует список. «Сегодня» = ON_SITE + PLANNED на сегодня.
11. Карточка/строка водителя: имя, ✓, рейтинг, машина, страны **этой поездки**, статус («На месте · МЦПС · подтверждено …» или «28.09, ~18:00»), действия: позвонить, чат, «Пригласить к грузу».
12. Фильтр по стране учитывает `tripCountryIds` анонса (не только профиль).

## Готово, когда
- Водитель за 3 нажатия публикует «буду на МЦПС послезавтра, KZ/UZ».
- Логист видит его в полосе дней на нужную дату и в фильтре по Узбекистану.
- Водитель с анонсом на другом терминале не попадает в фильтр по МЦПС.
- «Повторить прошлый анонс» работает одной кнопкой.
- Просроченный PLANNED-анонс сам уходит из ленты.
