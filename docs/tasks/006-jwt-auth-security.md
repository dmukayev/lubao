# 006 — Настоящая авторизация (JWT) и защита SMS-кода

Статус: готово

## Что сделано (2026-10-04)
- JWT access (15 мин) + opaque refresh (хэш SHA-256 в новой модели `Session`),
  ротация при `/auth/refresh` с reuse-detection (повторное использование
  уже заменённого токена отзывает сессию), выход через `/auth/logout`.
  Скользящий TTL по роли: DRIVER 90д / COMPANY 30д / ADMIN 12ч.
  Несколько устройств одновременно; `GET /auth/sessions`,
  `DELETE /auth/sessions/:id`, `DELETE /auth/sessions?except=current`.
- `DevAuthGuard` и `X-User-Id` удалены полностью; `JwtAuthGuard` проверяет
  Bearer-токен, статус пользователя в БД и живость сессии на каждый запрос
  (поэтому «выйти на всех остальных» действует уже на следующий запрос
  второго устройства, а не только после истечения access-токена).
- Маршруты переименованы: `/auth/phone/request-code`, `/auth/phone/verify`,
  `/auth/email/login`, `/auth/admin/login`; добавлен `GET /auth/me`.
- SMS: максимум 5 неверных попыток на код (6-я — код сгорает), лимит
  20 запросов/час на IP (+`trust proxy` в `main.ts`, иначе за nginx лимит
  не работал бы), `crypto.randomInt` в `MobizonSmsProvider`, сравнение кода
  через `crypto.timingSafeEqual`.
- Админ: блокировка на 15 мин после 5 неверных попыток (Redis-счётчик),
  каждая попытка логируется в `audit_log`. Демо-пароль поднят до 14 символов
  (`DemoLubao2026!`), обновлён в seed и `DEMO_CREDENTIALS.md`;
  `prisma:seed:demo` отказывается запускаться при `NODE_ENV=production`.
- Flutter (`lubao_core`): токены в `flutter_secure_storage`, Dio-интерсептор
  с авто-обновлением по 401 (с защитой от параллельных refresh) и выходом
  при неудачном refresh; восстановление сессии при перезапуске через
  `GET /auth/me`; экран «Мои устройства» в `lubao_app` (профиль водителя и
  компании); `lubao_admin` получил тот же интерсептор + сообщение о
  блокировке.
- Тесты (Jest): `jwt-auth.guard.spec.ts`, `token.service.spec.ts`,
  `session.service.spec.ts`, `sms.service.spec.ts`, `auth.service.spec.ts`
  (40 тестов, все зелёные). Все критерии «Готово, когда» проверены вживую
  через curl (401 без токена/с X-User-Id, 6-я попытка кода, два устройства +
  «выйти на всех остальных», вход в приложение/админку с кодом `1111` в деве).
  Flutter-часть проверена `flutter analyze` + `flutter build web` (без
  живого прогона в браузере).

## Проблема (найдено при ревью 2026-10-04)
- `backend/src/common/dev-auth.guard.ts` доверяет заголовку `X-User-Id`. Любой, кто знает или подберёт id, действует от имени любого пользователя, включая админа.
- Проверка SMS-кода не ограничивает число попыток: 4-значный код (10 000 вариантов) перебирается за минуты.
- Нет лимита запросов кода на IP.
- `MobizonSmsProvider.generateCode` использует `Math.random()` — не криптостойкий генератор.

## Что сделать
1. JWT: access-токен (15 мин) + refresh-токен (хранится хэшем в БД, ротация при обновлении, отзыв при выходе).
   - Срок refresh (скользящий — продлевается при каждом использовании): **водитель — 90 дней, логист/владелец компании — 30 дней, админ — 12 часов**. Водитель на границе может долго быть без связи — не выкидывать его.
   - **Несколько устройств одновременно — разрешено.** Каждое устройство = своя сессия (refresh-токен + название устройства, платформа, последний вход).
   - Экран «Мои устройства» в настройках (водитель и логист): список сессий, «Выйти на этом устройстве», «Выйти на всех остальных». API: `GET /auth/sessions`, `DELETE /auth/sessions/:id`, `DELETE /auth/sessions?except=current`.
   - `POST /auth/phone/verify`, `/auth/email/verify` (логист — код на email, без пароля; отправка кода `POST /auth/email/request`, те же лимиты, что у SMS), `/auth/admin/login` (email + пароль) возвращают пару токенов.
   - `POST /auth/refresh`, `POST /auth/logout`.
2. Заменить `DevAuthGuard` на `JwtAuthGuard` (глобально), роли — из токена + проверка в БД. `@Public()` оставить.
   - Dev-режим через `X-User-Id` удалить полностью (не оставлять «за флагом»).
3. SMS-код:
   - максимум 5 неверных попыток на код → код сгорает;
   - лимит 20 запросов кода в час на IP;
   - генерация через `crypto.randomInt(1000, 10000)`;
   - сравнение кода через `timingSafeEqual`.
4. Flutter (`lubao_core` / `api_client.dart`): хранить токены в `flutter_secure_storage`, Dio-интерсептор: Authorization header, автообновление по 401, выход при неудачном refresh.
5. Админка: 2FA пока не делаем (решение 2026-10-04). Минимум: пароль от 12 символов, блокировка на 15 минут после 5 неверных попыток, журнал входов админа в `audit_log`. Демо-пароль админа (`Demo12345!`, 10 символов) обновить в seed и `DEMO_CREDENTIALS.md` под новое правило.
6. `DEMO_CREDENTIALS.md` — оставить, но убедиться, что демо-сид не запускается в prod (проверка `NODE_ENV`).

## Готово, когда
- Запрос без токена или с чужим/просроченным токеном → 401. Заголовок `X-User-Id` ни на что не влияет.
- 6-я неверная попытка ввода кода → отказ, нужен новый код.
- Тесты: guard, refresh-ротация, лимиты попыток и IP.
- Вход в приложение и админку работает как раньше (в dev — код 1111).
- Можно войти с двух устройств; «Выйти на всех остальных» разлогинивает второе устройство при следующем запросе.
