## Что сделать
1. **Справочник.** `body_types.profile` (enum: `VOLUME`, `PLATFORM`, `CONTAINER`, `BULK`, `TANK`, `CAR_CARRIER`) и `body_types.fields` (JSON: массив полей `{key, kind: number|enum|bool|range, unit, required, forVehicle, forCargo, options?}`), сид по таблице ниже; админка — редактор полей типа кузова. Миграция: существующим типам проставить профиль и поля; существующие значения машин (`volumeM3`, `palletsEuro`, Д×Ш×В) скопировать в `specs` объёмных, у остальных типов — обнулить и не показывать.

| Профиль | Машина | Груз |
|---|---|---|
| VOLUME (тент, изотерм, реф) | тоннаж, м³, паллеты, Д×Ш×В (шаблоны 033); реф — `tempMin/tempMax` | вес, м³/паллеты; реф — нужная температура |
| PLATFORM (бортовой, трал) | тоннаж, длина платформы; трал — высота площадки, допуск негабарит | вес, Д×Ш×В груза, негабарит |
| CONTAINER | типы 20'/40'/45' (мультивыбор), число мест | тип контейнера, количество |
| BULK (самосвал, зерновоз) | тоннаж, м³ кузова | вес, м³ |
| TANK (цистерна) | литры, продукт (топливо / пищевое / химия / газ), секции | продукт, литры |
| CAR_CARRIER (автовоз) | число машин, открытый/закрытый | число машин, тип авто |

2. **Данные.** `Vehicle.specs` и `Cargo.specs` (JSON), валидация на сервере по `fields` типа кузова (обязательность, диапазоны, enum). Старые колонки объёма/паллет оставить как проекцию `specs` для VOLUME (чтобы 033/037 не переписывать), остальным — null.
3. **Гараж:** форма добавления/правки машины строится по `fields` выбранного типа (после техпаспорта); для VOLUME — чипы шаблонов как сейчас, для остальных — свои поля; карточка машины — строка по профилю («Цистерна · 30 000 л · пищевая · 3 секции», «Автовоз · 8 машин · открытый», «Трал · 40 т · площадка 0,9 м · негабарит»).
4. **Публикация груза:** логист выбирает требуемый кузов (один или несколько совместимых) → форма показывает поля груза этого профиля; «Подходит N водителям» считается по профилю.
5. **Лента и «Кто свободен»:** отсев по профилю — вес всегда; м³/паллеты только VOLUME; литры и продукт — TANK; число машин — CAR_CARRIER; контейнер — совпадение типа. Правило вместимости/догруз (037) — только VOLUME, у остальных одна активная сделка на машину.
6. **Логист, карточка водителя и отклик:** строка машины по профилю; в пакете документов (044) — тоже.
7. **Регистрация водителя** (шаг «Какая у вас машина?», 045 п.5): тип кузова (миниатюры, эталон 29) + **основа этого типа** — поле профиля с признаком `primary` (одно число или чип, не форма): тент/изотерм/бортовой/трал/самосвал/зерновоз — тоннаж; реф — тоннаж + режим; контейнеровоз — 20'/40'/45'; цистерна — литры + продукт; автовоз — число машин. **Тоннаж не универсален** — у автовоза и контейнеровоза его не спрашивать. Сохраняется как предпочтение водителя (`preferredSpecs` JSON), остальные поля профиля — в гараже при добавлении реальной машины.
8. ARB 4 языка (названия полей и опций — из справочника, JSON {kk,ru,zh,en}); единицы через l10n. Тесты: валидация specs по профилю, отсев по каждому профилю, миграция на демо-базе (тент сохранил м³/паллеты, цистерна без них). e2e: добавить цистерну → форма без паллет; груз «цистерна, 20 000 л» виден цистерне и не виден тенту.

## Готово, когда
- У цистерны, автовоза, трала в гараже и у логиста — свои параметры, без «м³ · пал.».
- Логист публикует груз под конкретный кузов и видит только осмысленные поля.
- Новый тип кузова с полями добавляется в админке без релиза.
