# 003 — Авторизация и SMS-шлюз

Статус: не начато

## Цель
Водитель входит по номеру телефона и SMS-коду, компания — по email и паролю.

## Что сделать
### Бэкенд
1. Модуль `sms` с интерфейсом провайдера:
   - `ConsoleSmsProvider` — dev: код всегда `1111`, пишется в лог, SMS не отправляется.
   - `MobizonSmsProvider` — prod, API Mobizon.
   - Выбор через `SMS_PROVIDER` в .env.
2. `POST /auth/phone/request` — отправка кода; `POST /auth/phone/verify` — проверка, выдача JWT (access + refresh).
3. Лимиты (Redis): 1 SMS в минуту и 5 в час на номер, 20 в час на IP. Код живёт 5 минут, 5 попыток ввода.
4. Номера: только +7 (Казахстан) для водителей.
5. Компании: `POST /auth/email/login`, аккаунты создаёт/подтверждает админ, приглашение сотрудников по email.

### Flutter
6. Экраны: выбор языка → «Я водитель / Я логист» → ввод телефона (маска +7) → ввод кода (автоподстановка из SMS на Android, таймер повторной отправки 60 с).
7. Хранение токенов в secure storage, автообновление access-токена.

## Готово, когда
- В dev вход работает с кодом 1111 без реальных SMS.
- Лимиты покрыты тестами (6-й запрос за час — отказ с понятной ошибкой).
- Переключение на Mobizon — только сменой .env.
