# 012 — Профиль компании: проверка, сотрудники, контакты логиста, WeCom

Статус: не начато · после 006

Эталон: `design/screens/08-company-profile.png`. Решения — `docs/decisions.md` (2026-10-04, «Компания»).

## Текущее состояние (ревью 2026-10-04)
`company_profile_screen.dart`: название, рейтинг, плашка, email, язык, список сотрудников (только роль, без имён), выход. Нет редактирования, приглашений, документов компании, WeCom. `Company.name` — одно поле, а нужно два языка.

## Что сделать

### Данные (миграция)
1. `Company`: `nameLocal` (на языке страны компании, напр. 新疆一道物流) + `nameRu` (обязательно оба), `logoKey` (MinIO), `wecomWebhookUrl` (шифровать в БД).
2. `CompanyMember` / `User`: у каждого сотрудника — `fullName`, `contactPhone`, `wechatId` (необязательно). Это контакты, которые видит водитель.
3. Приглашения: таблица `company_invites` (email, роль, токен, срок 7 дней, статус).

### Обязательные поля (решение 2026-10-04)
Принцип как у водителя: при регистрации — минимум, остальное — при первой попытке опубликовать груз.

| Поле | Обязательно | Когда |
|---|---|---|
| Название на языке страны | да | регистрация |
| Название по-русски | да, но предзаполняется ИИ-переводом (модуль `translation`), можно поправить | регистрация |
| Страна | да | регистрация |
| Город | да, свободный ввод | регистрация |
| Регистрационный номер: 统一社会信用代码 (18 символов, буквы/цифры) или БИН (12 цифр) — валидация формата по стране | да | перед первой публикацией |
| Свидетельство о регистрации (файл) | да | перед первой публикацией |
| Логотип, WeCom-бот | нет | когда угодно |
| Юридический адрес | не спрашивать (есть в реестре) | — |

Логист (личный профиль): имя — да (регистрация); email — да (вход); **телефон для водителей** — да, перед первой публикацией, любой код страны (+86, +7 …); WeChat ID — нет (рекомендуем); язык — автоматически.

**Регистрация компании** (~1 минута): email, пароль, имя, название, страна, город.
**Первое «Опубликовать груз»:** окно «Чтобы публиковать грузы» с недостающими полями (рег. номер, свидетельство, телефон) → после заполнения документ уходит на проверку, кнопка разблокируется после одобрения.

### Правила доступа
4. **Непроверенная компания не может публиковать грузы** — бэкенд отвечает 403 `COMPANY_NOT_VERIFIED`; в UI кнопка «Опубликовать груз» заблокирована, баннер «Публикация откроется после проверки». Смотреть водителей на точке и писать им можно.
5. **Проверка компании: один документ** — свидетельство о регистрации (营业执照 / справка о госрегистрации с БИН). Статусы как у водителя (none / pending / approved / rejected + причина). Удостоверение руководителя НЕ запрашиваем (решение 2026-10-04); админ может запросить дополнительный документ вручную в спорном случае (статус `ADDITIONAL_REQUIRED` + комментарий).
   `Company.isVerified` ставит админ после проверки по чек-листу (п. 5а), а не автоматически при загрузке документа.
5а. **Чек-лист проверки компании в админке** (галочки сохраняются в `audit_log`, одобрить можно только когда отмечены все обязательные):
   - компания найдена в официальном реестре (КНР: 国家企业信用信息公示系统; РК: поиск по БИН) — ссылка/скрин в комментарий;
   - название и рег. номер в документе совпадают с реестром;
   - звонок на **официальный номер компании из реестра** (не из заявки): подтверждено, что заявитель — сотрудник; имя подтвердившего — в комментарий;
   - домен email заявителя (подсказка: корпоративный домен компании — зелёный, бесплатная почта qq.com / 163.com / gmail.com — жёлтый, требует внимания на звонке).
   Очередь проверки — та же, что для водителей, с фильтром «компании».
6. **Роли:**
   - **Владелец** — **все права логиста** (публикует грузы, пишет и звонит водителям, ведёт сделки) + данные компании, документы, сотрудники, WeCom, редактирование любых грузов и сделок. Компания из одного владельца — полноценная, приглашать сотрудников не обязательно (решение 2026-10-04).
   - **Логист** — видит все грузы, сделки и чаты компании (чтобы подменить коллегу); редактирует/закрывает свои грузы и ведёт свои сделки. Данные компании и сотрудников — только просмотр.
   - Проверки ролей — на бэкенде (тесты на каждое правило).
7. **Контакты в грузе — конкретного логиста**, который его опубликовал: имя, телефон, WeChat. Кнопки «Позвонить» / «Написать» у водителя ведут к нему. Если логист удалён из компании — его грузы переходят владельцу.

### Адаптивный кабинет логиста (решение 2026-10-04)
Одно приложение, данные и права одинаковые на любом экране; меняется только раскладка.
- **Шире 1024 px** — боковое меню как на макетах 06/08: Водители на точке · Грузы компании · Сделки · Чаты · Компания; внизу меню — переключатель языка 中文 / RU / KZ / EN и блок пользователя.
- **Уже 1024 px (телефон)** — нижнее меню из 5 вкладок: **Водители · Грузы · Чаты · Сделки · Компания**. Сейчас в `company_shell.dart` 4 вкладки и нет «Чатов» — добавить.
- «Кто будет на Хоргосе»: на телефоне полоса дней прокручивается, водители — карточками вместо строк таблицы.
- Профиль компании: на телефоне те же блоки одной колонкой в том же порядке (баннер → компания → проверка → сотрудники → мой профиль → WeCom).
- На телефоне: свидетельство можно снять камерой; «Позвонить»/WhatsApp открывают нативные приложения.

### Экран (веб и мобильная версия)
8. По макету: баннер (если не проверена) → карточка компании (лого, два названия, город, рейтинг, «Изменить» — только владельцу) → «Подтвердите компанию» — один документ и пояснение «сверим с реестром и позвоним на номер из реестра, обычно до 1 рабочего дня» (скрывается после проверки) → «Сотрудники» (+ Пригласить, роли, «Отправить ещё раз», «Управлять»: сменить роль / удалить) → справа «Мой профиль» (имя, телефон для водителей, WeChat, язык, мои устройства) и «Уведомления в WeCom» (адрес бота, «Сохранить», «Отправить тест», ссылка на инструкцию).
9. Приглашение: владелец вводит email и роль → письмо со ссылкой → сотрудник задаёт пароль и заполняет «Мой профиль». (Отправку email можно временно заменить ссылкой-приглашением, которую владелец копирует сам — решить в плане.)
10. Все строки — ARB (kk/ru/zh/en).

## Готово, когда
- Непроверенная компания не публикует груз ни через UI, ни через API.
- Логист видит грузы коллеги, но не может их изменить (тест API).
- Водитель в карточке груза видит имя, телефон и WeChat того логиста, который опубликовал груз.
- Владелец приглашает сотрудника, тот входит и появляется в списке.
- «Отправить тест» доставляет сообщение в группу WeCom.
