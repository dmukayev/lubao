# 042 — «Живое приложение»: push, почта, WhatsApp-код, фоновые задачи

Статус: в работе (2026-10-07). Готово и прошло e2e (iPhone 17, 16e, админка 1280/390): п.0 — геозона 10 км (миграция проверена на демо-базе), поздний анонс до конца следующего дня, демо-сид ON_SITE, гашение анонса в транзакции; п.3 — три канала кода (WhatsApp / Telegram Gateway / SMS), выбор на экране входа и «отправить по-другому», блок «Каналы кода входа» в админке; п.4 — архив 3 дня (и при правке груза), поле «срок архива» убрано из админки. Сервер готов (юнит-тесты): п.1 — кнопки в push (категории), ссылки push — маршруты приложения; п.2 — письма подтверждения и сброса пароля, .well-known для ссылок-приглашений. Дальше: п.1 в приложении (Firebase за флагом PUSH_ENABLED, кнопки, переход по тапу), п.2 в приложении (associated domains / App Links), живые проверки — нужны ключи владельца. Оценка: 1,5 дня. **Живая проверка push (2026-10-07):** Huawei Y7 2019 (DUB-LX1, Android 8.1), сборка PUSH_ENABLED, приложение закрыто — push «Вас выбрали» (DEAL_SELECTED, FCM) пришёл, тап открыл сделку. iPhone — push заблокирован: команда Apple «Personal Team» не даёт права Push Notifications, нужен платный Apple Developer Program; приложение на iPhone установлено без push. На живой проверке найдены и исправлены: «Выйти» не срабатывал при включённом push, гараж на узком экране с шрифтом ×1,3, ECONNREFUSED при открытии документа в админке.
Опирается на 011 (бэкенд push готов, SDK нет), 018 (планировщик — не начато). Пилот — Казахстан: FCM + APNs; JPush — после пилота (не удалять заготовки).

## Что сделать
1. **Push-SDK в приложении:** `firebase_messaging` (Android/iOS) + APNs через Firebase; `registerDeviceToken()` при входе и смене токена; удаление токена при logout; обработка тапа по push → экран (чат/сделка/анонс) через go_router deep link; foreground — локальное уведомление. Разрешение запрашивать после первого осмысленного действия (отклик/анонс), не на старте. Push с кнопками «Да / Уехал» для правила свежести (040 п.4). Сборка для КНР без Firebase — отдельный flavor `cn` (заглушка, не реализовывать).
2. **Почта:** `EmailProvider` с SMTP (nodemailer) — env `SMTP_HOST/PORT/USER/PASS/FROM`; шаблоны на 4 языках (приглашение, сброс пароля, подтверждение email, «Договорились?»-дайджест). Приглашение — **https-ссылка** `https://<APP_HOST>/invite/<token>` (universal link / app link; на вебе открывает экран принятия), `lubao://` убрать. Проверка доставки в gmail/mail.ru/qq.com — в итоге задачи.
3. **Каналы кода входа — WhatsApp, Telegram, SMS, управляются из админки** (решение 2026-10-07): в `sms`-абстракции три канала — `whatsapp` (Meta Cloud API, шаблон authentication с кнопкой копирования, env `WHATSAPP_TOKEN/PHONE_ID/TEMPLATE`), `telegram` (Telegram Gateway `gateway.telegram.org`, env `TELEGRAM_GATEWAY_TOKEN`; ошибка «нет Telegram на номере» → следующий канал), `sms` (Mobizon, как сейчас). В админке → Настройки: блок «Каналы кода входа» — вкл/выкл каждого и порядок (хранить в `app_settings`, без релиза); без ключей канал недоступен и в админке показан серым. На экране входа водитель выбирает, куда прислать код (кнопки только включённых каналов; по умолчанию — первый по порядку), при ошибке канала сервер сам берёт следующий и отвечает, куда ушёл код; «Не пришло? Отправить по-другому». Лимиты и dev-коды — общие для всех каналов. Тесты: порядок/фолбэк, выключенный канал не используется, выбор пользователя уважается.
4. **Планировщик (018):** `@nestjs/schedule` + BullMQ с блокировкой в Redis; задачи идемпотентны:
   - курс НБ РК ежедневно 10:00 Алматы + при старте, если курса на сегодня нет; ручная правка в админке;
   - «Договорились?» через 2 ч после `contact_event` (push с кнопками «Да → выбрать груз / Нет»);
   - свежесть анонсов (040 п.4) — все таймеры;
   - архив грузов через 3 дня после `readyDate` (не 48 ч), истечение откликов `INVITED` через 24 ч;
   - удаление геопозиций старше 30 дней; чистка просроченных сессий/кодов.
5. **WeCom:** сообщения чата тоже уходят в WeCom-бот компании (сейчас только NEW_RESPONSE/DEAL_STATUS — `chats.service.ts:300` без `companyId`). Текст на языке компании.
6. Все письма/пуши/WeCom — **без «Хоргос»**, город из справочника; тексты в 4 языках через l10n-таблицу на сервере.
7. Тесты: планировщик (идемпотентность, блокировка), фолбэк WhatsApp→SMS, формирование deep link; живая проверка push на реальном Android и iPhone (ручной шаг — скриншоты в итог); e2e: push-токен регистрируется (мок).

0. **Из ревью 040:** радиус геозоны Хоргоса — 10 км (сид и миграция данных для существующей точки); `lat/lng` Хоргосу при миграции; push «Ещё ищете груз?» с кнопками «Да / Уехал»; анонс на «сегодня» после 22:00 не гасить в полночь; демо-сид ON_SITE с `lastConfirmedAt`; `completeArrivalForConfirmedDeal` в транзакции.

## Готово, когда
- Водитель с закрытым приложением получает «Вас выбрали» и «Ещё ищете груз?» с кнопками; тап открывает нужный экран.
- Логист получает письмо-приглашение по https-ссылке и письмо сброса пароля.
- Код входа приходит в WhatsApp, без WhatsApp — SMS.
- Курс обновляется сам; «Договорились?» приходит через 2 ч после звонка; анонсы гаснут по правилу.
