# 034 — Сквозные сценарии: робот сам проходит приложение и админку

Статус: не начато · после 033. Оценка: 3–4 часа.
Решение: `docs/decisions.md` → «Сквозные сценарии — критерий готовности» (2026-10-06).


> 2026-10-06: на Mac пользователя симуляторы уже установлены (iOS 26.3). Для сценариев водителя использовать **iPhone 17** (основной) и **iPhone 16e** (меньший экран — проверка переполнений). Запуск: `xcrun simctl boot "iPhone 17"` → `flutter test integration_test -d "iPhone 17"`.

## Зачем
Ошибки вроде «кнопка чата не нажимается», «белый экран в карточке», «фильтр показывает не то» находил пользователь руками. Юнит-тесты их не ловят. Нужны записанные сценарии, которые робот проходит как человек — после каждой задачи.

## Почему не «просто Playwright по странице»
Flutter Web рисует интерфейс на холсте (CanvasKit) — в DOM нет кнопок и полей, робот «не видит» их; поэтому ввод через CDP в 028/030 не завёлся. Решение — два уровня:
- **Flutter `integration_test`** — основной: сценарии на Dart, находят виджеты по `Key`/тексту, работают в Chrome (`flutter drive -d chrome` / `web-server`) и в симуляторе iPhone.
- **Playwright** — только для админки как веб-страницы (дымовой прогон): включить **семантику Flutter** (`SemanticsBinding.instance.ensureSemantics()` при флаге `--dart-define=E2E=true`), тогда у кнопок и полей появляются ARIA-подписи, и Playwright кликает `getByRole('button', { name: 'Подтвердить' })`.

## Что сделать

### Инфраструктура
0. **Сначала — сборка под симулятор.** Пользователь ни разу не запускал приложение в симуляторе (только на iPhone по кабелю). Проверить `flutter run -d "iPhone 17"` из `apps/lubao_app`; если падает — починить (вероятные причины: ручные правки `post_install` в `ios/Podfile` из коммита 2dfc83b2, `EXCLUDED_ARCHS`/arm64 для симулятора, поды без симуляторных срезов). Правки не должны сломать сборку на реальный iPhone — проверить обе. Записать в статус задачи, что было.
1. `apps/lubao_app/integration_test/`, `apps/lubao_admin/integration_test/` + `test_driver/`. Ключевым виджетам — стабильные `Key('…')` (кнопки действий, поля ввода, вкладки, карточки в списках). Тексты в тестах — через ARB-ключи, не строками (язык теста — ru).
2. **Тестовое окружение:** скрипт `scripts/e2e.sh`:
   - поднимает docker-сервисы (postgres, redis, minio, ocr), **отдельную базу `lubao_e2e`**, `prisma migrate deploy` + детерминированный сид `prisma/seed-e2e.ts` (фиксированные водитель, логист, компания, админ, грузы, анонсы; **только синтетические данные**);
   - SMS/email — консольные провайдеры с фиксированными кодами (1111 / 111111), DeepSeek — `Noop` или заглушка с предсказуемым ответом, push — консоль;
   - запускает backend на отдельном порту, затем сценарии, затем гасит всё; итог — код возврата 0/1.
3. Скриншот на каждом ключевом шаге и при падении → `test-results/e2e/<сценарий>/NN-шаг.png` (папка в `.gitignore`), отчёт `test-results/e2e/report.md`: сценарий, шаги, ✅/❌, путь к скриншоту, текст ошибки.

### Сценарии (минимум)
**Водитель (приложение, Chrome + симулятор iPhone):**
4. Вход по телефону (код 1111) → главная без ошибок → анонс «Буду на точке» (связка из гаража) → карточка анонса с датой.
5. Лента → карточка груза → «Написать» → чат открылся → отправить сообщение → оно в списке «Чаты».
6. Отклик на груз → (логист выбирает — шаг через API или параллельный сценарий) → «Подтверждаю перевозку» → статусы «Загружен» → «В пути».
7. Гараж: добавить прицеп с синтетическим фото техпаспорта → поля предзаполнены распознаванием → выбор шаблона размера (033) → «на проверке».

**Логист (приложение, Chrome):**
8. Регистрация компании (email + пароль) → баннер «Публикация откроется после проверки» → загрузка синтетического свидетельства → кнопка «Опубликовать» заблокирована.
9. (После одобрения админом) публикация груза с объёмом → «Кто будет на точке» → чат с водителем → выбор водителя из откликов → сделка.

**Админ (админка, Chrome, ширина 1280 и 390):**
10. Сводка: каждая плитка и строка «Требует внимания» открывают список с правильным фильтром (сверить число на плитке с числом строк).
11. Проверка: водитель из очереди → блок «Распознано» с полями → подтвердить → водитель «Проверен»; компания → подтвердить → у логиста кнопка публикации разблокирована.
12. Чёрный список: заблокировать водителя с идентификаторами → зарегистрировать нового с тем же синтетическим ИИН → в проверке ⛔, обычная кнопка «Подтвердить» неактивна.
13. Жалоба: «Новые» → «В работе» (не исчезает) → решение + ответ → «Закрытые».
14. Карточки водителя, компании, груза, сделки открываются без белого экрана; редактирование имени водителя не меняет госномер.

### Правило
15. В `CLAUDE.md` (раздел «Как работать») — добавлено архитектором: задача считается готовой, только если `scripts/e2e.sh` зелёный; новый экран или действие — новый шаг в сценарии.
16. `docs/testing/smoke-test.md` — оставить только то, что робот проверить не может: реальные push на телефоне, камера и фото с настоящего iPhone, работа при плохой связи, вид на маленьком Android.

17. **Безопасная зона:** в сценариях на симуляторах iPhone 17 и 16e на каждом экране проверять, что верхний интерактивный элемент ниже `MediaQuery.padding.top`, а нижние закреплённые кнопки выше `MediaQuery.padding.bottom` (общий хелпер в тестах); скриншоты — с видимой строкой статуса. Плюс **разовый обход всех экранов** приложения (водитель и логист) и мобильной админки — не только тех, что в сценариях: открыть каждый маршрут из `app_router.dart`, проверить безопасную зону и отсутствие переполнений, найденное — исправить в этой же задаче, список экранов — в статус.

## Готово, когда
- `scripts/e2e.sh` одной командой поднимает окружение, проходит сценарии 4–14 и выдаёт отчёт со скриншотами; на текущем коде — зелёный (или в отчёте перечислены найденные баги, и они исправлены в этой же задаче).
- Сценарии работают и в Chrome, и в симуляторе iPhone (водитель).
- Повторный запуск даёт тот же результат (детерминированный сид, нет зависимости от времени суток — даты в сиде относительно «сегодня»).
